# 발표자 노트: train_val_test

번호는 슬라이드 하단 번호입니다 (표지 제외).

## 1. 오늘의 질문

100명에게 아무 뜻 없는 난수를 5000개씩 줬습니다. 정답은 동전을 던져 정했습니다. 이 데이터로 동전 앞뒤를 맞힐 방법은 없습니다. 찍으면 50퍼센트가 정상입니다. 그런데 지난 시간에 배운 교차 검증까지 제대로 했는데 정확도가 87퍼센트가 나왔습니다. 무엇이 잘못됐을까요? 오늘은 이렇게 성능이 부풀려지는 실수, 데이터 누수를 다룹니다.

## 2. 세 데이터의 역할

먼저 세 데이터의 역할을 정리합니다. train으로는 가중치를 배웁니다. val, 검증 데이터로는 람다 같은 설정값이나 여러 모델 중 하나를 고릅니다. 지난 시간처럼 train 안에서 돌아가며 교차 검증을 해도 됩니다. test, 시험 데이터는 모든 결정이 끝난 뒤 마지막에 딱 한 번 성능을 잽니다. 핵심은 정보가 한 방향으로만 흐른다는 겁니다. test의 정보가 어떤 식으로든 학습이나 선택으로 거꾸로 흘러 들어가면, test 점수는 더 이상 처음 보는 데이터의 성능이 아닙니다. 이것이 데이터 누수입니다.

## 3. test 로 여러 번 고르면: 운이 점수에 섞인다

가장 흔한 누수는 test를 여러 번 보는 것입니다. 진짜 실력이 모두 똑같은 후보들을 test로 재면, 점수는 운에 따라 조금씩 위아래로 흔들립니다. 그중 가장 잘 나온 것을 고르면, 고른 점수는 진짜 실력보다 높을 수밖에 없습니다. 운이 좋았던 걸 골랐으니까요. 잡음 크기를 1로 두면, 후보 5개 중 최고는 평균 1.16만큼, 50개 중 최고는 2.25만큼 부풀려집니다. 람다 10개에 모델 5종류만 해도 후보가 50개입니다. 그래서 고르기는 val로 하고, test는 마지막에 한 번만 봅니다.

## 4. 데이터 누수 (Data Leakage)

데이터 누수는 시험 데이터의 정보가 학습 과정에 몰래 새어 들어가는 것입니다. 오늘은 세 가지 대표적인 경우를 봅니다. 첫째, 특징 고르기나 표준화 같은 전처리를 전체 데이터로 한 다음에 나누는 경우. 둘째, 같은 사람의 데이터가 학습과 시험 양쪽에 들어가는 경우. 셋째, 미래 데이터로 학습하고 과거를 시험하는 경우입니다. 공통점은 실제로 모델을 쓸 때는 없을 정보를 시험할 때 썼다는 것입니다.

## 5. 누수 1: 전체 데이터로 특징을 고르면

처음의 동전 실험입니다. 범인은 숫자 고르기였습니다. 5000개 중 정답과 상관이 가장 큰 숫자 20개를 고를 때 100명 전체를 봤습니다. 시험 볼 학생까지 포함해서요. 5000개나 되면 우연히 정답과 맞아 보이는 숫자가 생기는데, 그 우연에는 시험 학생의 정답도 들어 있습니다. 그 숫자로 교차 검증을 하니 87퍼센트가 나왔습니다. 고를 때 이미 답을 본 셈입니다. 숫자 고르기를 각 조각의 학습 80명 안에서만 하면 49퍼센트, 찍기와 같습니다. 50번 반복해도 누수 쪽은 모두 75퍼센트 이상, 정상 쪽은 모두 61퍼센트 이하였습니다.

## 6. 누수 1: 표준화도 학습 데이터로만

특징 고르기만이 아닙니다. 표준화도 마찬가지입니다. 1부터 10까지 중 1에서 7을 train, 8, 9, 10을 test로 둡니다. 평균과 표준편차를 전체로 구하면 5.5와 2.872이고, test의 z는 0.87에서 1.57로 평범해 보입니다. train으로만 구하면 4와 2.0이고, test의 z는 2에서 3으로 학습 범위를 한참 벗어난 값이라는 게 드러납니다. 실제로 쓸 때는 새 데이터의 값을 미리 알 수 없으니 정상 쪽이 맞습니다. 전처리도 모델의 일부라고 생각하고 train으로만 fit하고, val과 test에는 apply만 합니다. scikit-learn의 Pipeline으로 묶으면 교차 검증 안에서도 자동으로 이렇게 됩니다.

## 7. 누수 2: 같은 환자가 학습과 시험 양쪽에

두 번째는 의료 영상 AI에서 실제로 자주 발견되는 누수입니다. 환자 100명에게서 사진을 5장씩 찍었습니다. 한 환자의 사진 5장은 서로 아주 비슷해서 그림에서 작은 덩어리로 뭉쳐 있습니다. 사진 단위로 섞어서 나누면 왼쪽처럼 한 덩어리 안에 학습 사진과 시험 사진이 섞입니다. 그러면 모델은 같은 환자의 다른 사진을 보고 아 이 사람이네 하고 답을 맞힙니다. 오차가 1.04로 아주 좋아 보입니다. 환자 단위로 나눠서 시험 환자는 학습에 한 번도 안 나오게 하면 3.65가 됩니다. 이게 처음 보는 환자에게 쓸 때의 진짜 성능입니다. scikit-learn에서는 GroupKFold로 나눕니다.

## 8. 누수 3: 미래로 과거를 맞히기

세 번째는 시간입니다. 매일 1씩 오르는 값을 1년 동안 쟀습니다. 날짜를 섞어서 나누면 시험 날짜 바로 어제와 내일이 학습 데이터에 있어서, 그 사이를 메우기만 하면 됩니다. 오차 0.79로 훌륭해 보입니다. 하지만 실제로 이 모델을 쓸 때는 내일을 예측해야 하고, 내일의 데이터는 없습니다. 앞 80퍼센트로 학습하고 뒤 20퍼센트를 시험하면, 모델은 학습 기간 끝의 값만 되풀이해서 오차가 44.1이 됩니다. 주가, 판매량, 센서처럼 시간 순서가 있는 데이터는 반드시 시간 순서로 나눕니다. scikit-learn에는 TimeSeriesSplit이 있습니다.

## 9. 누수를 막는 규칙

누수를 막는 규칙을 정리합니다. 데이터를 받으면 어떤 분석이나 그래프보다 먼저 test를 떼어 둡니다. 그래프를 보고 특징을 고르는 것도 정보가 새는 길이니까요. 표준화나 특징 고르기 같은 전처리는 train으로만 하고, Pipeline으로 묶어서 교차 검증 안에서 돌립니다. 같은 사람의 데이터는 같은 쪽에, 시간이 있는 데이터는 과거와 미래로 나눕니다. 그리고 test는 딱 한 번만 봅니다. 결과를 보고 모델을 다시 고치면 그 test는 이미 val이 된 겁니다. 헷갈릴 때는 실제로 모델을 쓸 때도 이 정보가 있을까라고 물어보면 됩니다.

## 10. 전체 흐름: 당뇨병 데이터 442명

지금까지의 원칙을 실제 당뇨병 데이터 442명에 한 흐름으로 적용해 봅니다. 먼저 train 265명, val 88명, test 89명으로 나눕니다. 릿지 람다 후보 5개를 train으로 학습하고 val로 비교해서 0.1을 고릅니다. 그다음 test로 딱 한 번 재서 53.79가 나왔고, 이 숫자를 최종 성능으로 보고합니다. 만약 test 점수를 보고 람다를 다시 고르면, 그때 나온 숫자는 그 test에서 운 좋게 잘 나온 값일 뿐이라 정직한 성능이 아닙니다.

## 11. 문제풀이

1번 답. a는 test의 값이 평균에 섞였으니 누수입니다. b는 정상입니다. c는 같은 학생이 학습과 시험 양쪽에 들어갈 수 있으니 누수이고, 학생 단위로 나눠야 합니다. 2번 답. 시간 순서로 나눕니다. 예를 들어 과거 3년으로 학습하고 그다음 1년을 시험하거나, TimeSeriesSplit을 씁니다. 3번 답. 20개 중 최고를 고르면 운이 섞여 부풀려집니다. 고르기는 val이나 교차 검증으로 하고, 고른 모델 하나만 새 test로 한 번 잽니다.

## 12. 실습

실습은 세 부분입니다. 첫째, 동전 실험을 직접 해서 전체로 숫자를 고르면 90퍼센트 가까이 나오고, Pipeline으로 묶어 교차 검증 안에서 고르면 찍기 근처로 떨어지는 걸 확인합니다. 둘째, 환자 누수와 시간 누수를 재현하고 GroupKFold와 TimeSeriesSplit으로 고칩니다. 셋째, 당뇨병 데이터로 train, val, test 3분할 파이프라인을 처음부터 끝까지 해 봅니다.

## 13. 정리

정리합니다. train으로 배우고, val이나 교차 검증으로 고르고, test는 마지막에 한 번만 봅니다. test로 여러 번 고르면 운이 점수에 섞여 부풀려집니다. 데이터 누수는 전체 데이터로 전처리하기, 같은 환자를 양쪽에 넣기, 미래로 과거를 맞히기처럼 실제로는 없을 정보를 시험 때 쓰는 것이고, 오늘 본 것처럼 성능을 크게 부풀립니다. 헷갈리면 실제로 쓸 때도 이 정보가 있을까를 물어보세요.
