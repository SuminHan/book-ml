고객 문의 자동 분류

대화형 인공지능고객응대 자동화상담 보조 · 문의 분산처리

은행 고객 문의 1만 3천 개, 담당 77곳. 문의를 맞는 팀에 보낼 수 있을까?

Colab 에서 열기노트북 받기 (.ipynb)

어떤 문제인가

입력 X문장
→ 모델 →다중 분류 (77가지)
출력 y (기대하는 답)의도 77가지 중 하나 (보낼 팀)

데이터

Banking77 · 약 1MB

PolyAI (Casanueva et al., 2020), 온라인 은행 고객 문의 13,083개를 의도 77가지로 나눈 영어 데이터 (GitHub PolyAI-LDN/task-specific-datasets)

무작위로 뽑은 몇 줄

textcategory

What is the refund procedure?request_refund
need to exchange currenciesexchange_via_app

데이터 통계

10,003줄 (데이터 파일의 줄 수. 문제의 '한 행' 은 아래 예시에서 따로 정한다)
2열
열종류빈칸고유값 수범위 · 대표값
text글자 · 범주010,003가장 흔한 값: I am still waiting on my card? (0.0%)
category글자 · 범주077가장 흔한 값: card_payment_fee_charged (1.9%)

데이터 모양 보기

의도(팀)별 문의 수: 많은 8개 · 적은 7개

77가지, 가장 많은 것과 적은 것이 약 5배 차이

문제를 정해 본 예시

① 한 행고객 문의 한 문장
② 입력 X문장
③ 출력 y의도 77가지 중 하나 (보낼 팀)
④ 평가지표정확도 + 의도별 정확도
⑤ 기준선가장 흔한 의도로 보내기

문제를 정할 때 처음 채워 보는 칸들입니다. 여기서 끝이 아니라, 시험 데이터를 어떻게 나눌지 · 틀렸을 때 손해가 얼마인지 · 예측 시점에 정말 알 수 있는 값인지 같은 칸을 더 붙일수록 좋은 문제가 됩니다.

노트북에서 나온 결과 (기준선 vs 모델)

baseline (always 'card_payment_fee_charged'): accuracy 1.3%
TF-IDF + logistic regression : accuracy 85.5%

평가지표 수식

정확도 (accuracy)맞힌 비율. 한쪽이 아주 드물면 '전부 흔한 쪽' 만으로도 높게 나온다
\text{Accuracy} = \frac{1}{n}\sum_{i=1}^{n} \mathbb{1}[\hat y_i = y_i]
