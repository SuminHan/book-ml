Machine Learning 1 (한국어)

1.2 머신러닝 문제 정식화와 세 갈래 분류

문제를 푸는 게 아니라, 먼저 문제를 “정의“하는 것부터

머신러닝을 처음 배울 때 흔히 하는 착각은 “어떤 알고리즘을 쓸까“부터 고민하는 것이다. 실전에서는 순서가 반대다 — 알고리즘을 고르기 전에, 문제 자체를 다음 세 가지로 명확히 정의해야 한다:

  1. 입력(input) \(x\): 무엇을 특징(feature)으로 쓸 것인가? (예: 집의 평수, 방 개수, 지어진 연도)
  2. 출력(output) \(y\): 무엇을 맞히고 싶은가? 연속값(회귀)인가, 범주(분류)인가?
  3. 가설(hypothesis) \(h\): 입력에서 출력으로 가는 함수를 어떤 형태로 근사할 것인가? (직선? 트리? 신경망?)

이 세 가지가 정해지지 않은 채로 “머신러닝으로 풀어보자“고 덤비면, 데이터를 아무리 모아도 무엇을 목표로 학습시켜야 하는지조차 불분명해진다. 부동산 가격을 예측하고 싶다면, \(x\)는 평수·방 개수·위치 같은 특징, \(y\)는 실제 거래 가격(연속값), \(h\)는 이 학기 초반에 배울 선형 함수부터 시작할 수 있다.

같은 틀을 완전히 다른 문제에 적용해보면 왜 이 세 가지가 “먼저” 정해져야 하는지 더 분명해진다. 이메일 스팸 필터를 만든다고 하자 — 여기서 \(x\)는 “메일 제목에 ’무료’가 들어있는가”, “발신자가 알려진 주소록에 있는가”, “느낌표 개수” 같은 특징들의 벡터이고, \(y\)는 스팸(1) 또는 정상(0)이라는 범주다. \(x\)와 \(y\)의 형태(연속값 vs 범주)가 다르니, 집값 문제와 스팸 문제는 \(h\)를 학습하는 손실함수도 달라져야 한다 — 이 차이가 정확히 이 절 뒤에서(“회귀 vs 분류”) 다룰 내용이다. 반대로 만약 \(x\)를 잘못 고른다면(예: 스팸 필터에 “메일이 도착한 요일“만 특징으로 쓴다면), 아무리 좋은 알고리즘을 써도 \(h\)가 배울 수 있는 신호 자체가 없다 — “어떤 알고리즘이 가장 정확한가“보다 “이 특징들이 애초에 정답과 관련이 있는가“가 항상 먼저 물어야 할 질문이다.

**학습(training)**이란, 주어진 데이터 \((x^{(1)}, y^{(1)}), \ldots, (x^{(m)}, y^{(m)})\)에 대해 \(h(x^{(i)})\)가 \(y^{(i)}\)에 최대한 가깝도록 \(h\)의 파라미터를 조정하는 과정이다. 여기서 위 첨자 \((i)\)는 “\(i\)번째 데이터 샘플“을 가리키는 표기로, 이 학기 내내 반복해서 쓰인다 — \(x^{(3)}\)이라면 세 번째 집의 특징 벡터라는 뜻이다.

\(m\)은 학습 데이터의 전체 개수(샘플 수)를 가리키는 또 다른 표준 표기다 — 앞으로 “\(m\)개의 데이터로 학습한다“는 표현이 계속 등장한다. 집값 예시로 표기를 정리하면: 집이 200채 있는 데이터셋이라면 \(m=200\)이고, \(x^{(37)}\)은 37번째 집의 (평수, 방 개수, 연식) 벡터, \(y^{(37)}\)은 그 집의 실제 거래가다. “학습“은 이 200개의 \((x^{(i)}, y^{(i)})\) 쌍을 전부 보고, 새로운(학습 데이터에 없던) 201번째 집이 들어와도 \(h(x^{(201)})\)이 합리적인 가격을 내놓도록 \(h\)의 파라미터를 조정하는 과정이다 — “학습 데이터를 외우는 것“이 아니라 “본 적 없는 데이터에도 일반화되는 규칙을 찾는 것“이라는 점이 핵심이며, 이 일반화 능력을 어떻게 검증하는지는 Chapter 6에서 엄밀하게 다룬다.

실습: 세 문제를 스스로 정식화해보기

직접 손을 움직여 정의해보면 감이 훨씬 빨리 잡힌다. 아래 세 시나리오 각각에 대해, 노트에 \(x\)(입력 특징), \(y\)(출력), \(h\)의 대략적인 형태(직선? 규칙 기반? 아직 모르겠다면 “이번 학기에 배울 것”)를 스스로 적어본 뒤 아래 힌트와 비교해보자.

  1. 신용카드 이상거래 탐지: 매 결제 건마다 “이 결제가 사기인가“를 즉시 판단해야 한다.
  2. 뉴스 기사 주제 자동 분류: 기사 본문을 읽고 “정치/경제/스포츠/문화” 중 하나로 태그를 붙인다.
  3. 공장 설비 잔여수명 예측: 센서 데이터(진동, 온도, 가동시간)로 “이 설비가 앞으로 며칠 더 버틸 것인가“를 추정한다.

힌트: (1)은 \(x\)=결제 금액·시간·가맹점 종류 등, \(y\)=사기/정상 (범주) → 분류. (2)는 \(x\)=기사 텍스트(나중에 단어 빈도나 임베딩으로 바꿀 것), \(y\)=4개 범주 중 하나 → 분류(다중 클래스). (3)은 \(x\)=센서 측정값들, \(y\)=남은 일수(숫자) → 회귀. 세 문제 모두 “정답 라벨이 있고 \(y\)가 범주냐 숫자냐“라는 같은 질문 하나로 갈렸다는 점에 주목하라 — 이 감각이 이번 학기 내내 새 문제를 만날 때마다 가장 먼저 꺼내 쓸 도구다.

세 갈래 분류: 무엇을 데이터로 갖고 있는가

머신러닝 문제는 크게 세 갈래로 나뉜다 — 그리고 이 분류는 알고리즘의 이름이 아니라, 어떤 형태의 데이터를 갖고 있고 어떤 신호로 학습하는가로 갈린다.

데이터 형태목표이번 학기 예시
지도학습\((x, y)\) 쌍새 \(x\)에 대한 \(y\) 예측회귀·분류, kNN, SVM, 트리, 신경망
비지도학습\(x\)만데이터의 숨은 구조 발견k-means, PCA, EM/GMM
강화학습상태·행동·보상누적 보상을 최대화하는 정책이번 학기(ML1)에서는 다루지 않음 — 강화학습·로봇 시뮬레이션을 전문으로 다루는 ML2에서
  • 지도학습(Supervised Learning): 입력과 정답이 쌍으로 주어진다 — “이 집의 평수/방 개수를 보고 가격을 맞혀라”(회귀), “이 이메일이 스팸인지 아닌지 맞혀라”(분류). ML1의 거의 모든 장이 여기 속한다. 지도학습 안에서도 다시 두 갈래가 갈린다 — 판별적(discriminative) 접근은 \(P(y|x)\)(x가 주어졌을 때 y의 확률)를 곧바로 학습하고(회귀·로지스틱회귀·SVM·신경망), 생성적 (generative) 접근은 \(P(x|y)\)(각 클래스가 데이터를 어떻게 만들어내는지)를 먼저 학습한 뒤 베이즈 정리로 뒤집어 \(P(y|x)\)를 얻는다(Chapter 3의 나이브베이즈·GDA). 같은 문제를 정반대 방향에서 접근하는 이 두 철학의 차이는 Chapter 3에서 자세히 다룬다.
  • 비지도학습(Unsupervised Learning): 정답 없이 데이터의 구조만 주어진다 — “이 고객들을 비슷한 성향끼리 묶어라”(군집화), “1000개 특징을 정보 손실 최소로 10개로 줄여라”(차원축소). Chapter 14~15에서 다룬다.
  • 강화학습(Reinforcement Learning): 정답이 아니라 보상만 주어지고, 에이전트가 시행착오로 좋은 행동을 스스로 찾아야 한다 — 체스나 바둑에서 “이 수가 정답이다“라고 알려주는 사람은 없지만, “이겼다/졌다“는 신호는 있다. 이번 학기(ML1)에서는 다루지 않는다 — ML1과 ML2는 서로 독립된 과목이고, ML2가 강화학습과 로봇 시뮬레이션을 처음부터 끝까지 전문으로 다룬다(ML2를 듣기 위해 ML1을 먼저 들을 필요는 없다).

세 갈래를 대표하는 유명한 시스템 하나씩

추상적인 정의보다 실제로 유명한 시스템 하나씩을 붙여보면 세 갈래의 차이가 훨씬 또렷해진다.

  • 지도학습 — ImageNet/AlexNet(이 챕터 도입부에서 이미 언급): 100만 장이 넘는 사진 각각에 사람이 미리 “고양이”, “자동차” 같은 정답 라벨을 붙여뒀다. 모델은 이 라벨을 보고 학습했다 — 라벨이 없었다면 애초에 이 방식 자체가 불가능했다.
  • 비지도학습 — 넷플릭스/스포티파이의 사용자 군집화: “당신과 비슷한 취향의 사람들이 좋아한 콘텐츠“를 추천할 때, 애초에 “이 사람은 그룹 3에 속한다“는 정답 라벨은 어디에도 없다. 시청·청취 기록만으로 비슷한 패턴을 가진 사용자들을 알고리즘이 스스로 묶어낸다.
  • 강화학습 — 딥마인드의 AlphaGo: 바둑의 “정답 수“를 사람이 알려준 적은 없다(애초에 최선의 수를 사람도 모른다). 대신 “이겼다(+1)/졌다(-1)” 라는 보상 신호만으로, 스스로 수백만 판을 두며 정책을 개선했다 — ML2에서 이 사고방식을 처음부터 다룬다.

이 세 갈래를 가르는 진짜 기준은 “얼마나 어려운 문제인가“가 아니라 **“손에 쥔 데이터에 무엇이 적혀 있는가”**라는 점을 다시 강조할 필요가 있다. 똑같이 “고객 데이터“를 갖고 있어도, 각 고객에게 “이탈했다/안 했다“는 라벨이 붙어 있으면 지도학습(이탈 예측) 문제가 되고, 라벨 없이 구매 패턴만 있으면 비지도학습(고객 세분화) 문제가 되며, “지금 어떤 할인 쿠폰을 보낼지 결정하고 그 결과로 매출이 오르는지 본다“는 시행착오 구조라면 강화학습 문제가 된다 — 같은 원본 데이터라도 무엇을 라벨로 볼 것인가에 따라 완전히 다른 문제가 된다. 이번 학기(ML1) 14개 챕터가 전부 지도학습(Chapter 2~13)과 비지도학습(Chapter 14~15)의 두 갈래에만 머무는 이유도 여기 있다 — 강화학습은 “정답 라벨이 아예 없고 보상 신호만 있다“는, 데이터의 형태 자체가 근본적으로 다른 문제라서 별도 과목(ML2) 하나를 통째로 할애할 만큼 다루는 도구와 이론이 다르다.

회귀 vs 분류: 같은 모델, 다른 출력

지도학습은 다시 출력이 연속값이냐 범주냐로 나뉜다: 회귀(regression)는 숫자를 예측한다(집값, 기온), 분류(classification)는 범주를 예측한다(스팸/정상, 개/고양이/새). 같은 선형 모델 \(w^Tx + b\)라도, 출력을 그대로 쓰면 회귀가 되고, 시그모이드를 씌워 0~1 확률로 해석하면 분류가 된다(둘 다 Chapter 2에서 다룬다) — 앞으로 몇 장 동안 이 패턴이 반복해서 나온다: 모델 구조는 비슷한데, 출력을 해석하는 방식과 손실함수(loss function)만 문제에 맞게 바뀐다. 같은 알고리즘이 두 문제 모두에 쓰이는 경우가 많으므로, 이 둘을 구분하는 눈은 이번 학기 내내 필요하다.

숫자로 직접 확인해보자. 어떤 선형모델이 \(w=[0.5,\ -2.0]\), \(b=1.0\)으로 학습됐고, 새 데이터 \(x=[3,\ 0.5]\)가 들어왔다고 하자. 먼저 \(w^Tx+b\)를 계산하면:

\[w^Tx+b = 0.5 \times 3 + (-2.0) \times 0.5 + 1.0 = 1.5 - 1.0 + 1.0 = 1.5\]

회귀로 쓴다면 이 계산 결과 \(1.5\)를 그대로 예측값으로 읽는다(예: “이 집은 1.5억 원”). 분류로 쓴다면 정확히 같은 \(1.5\)를 시그모이드 \(\sigma(z)=1/(1+e^{-z})\)에 통과시켜 \(\sigma(1.5)\approx0.82\)를 얻고, “이 이메일이 스팸일 확률 82%“로 읽는다 — 가중치 \(w\), 편향 \(b\), 입력 \(x\)는 완전히 동일한데, 오직 “출력을 어떻게 해석할 것인가“만 바뀌었다. 이 하나의 계산이 회귀도 되고 분류도 될 수 있다는 사실이, 왜 이 둘을 “같은 모델, 다른 출력“이라 부르는지의 핵심이다.

실습: 같은 계산, 두 가지 해석을 코드로 확인하기

위 손 계산을 그대로 코드로 옮겨서, “같은 숫자가 두 가지로 읽힐 수 있다“는 사실을 직접 확인해보자:

import math

def sigmoid(z):
    return 1 / (1 + math.exp(-z))

w = [0.5, -2.0]
b = 1.0
x = [3, 0.5]

z = sum(wi * xi for wi, xi in zip(w, x)) + b
print("z =", z)                        # 1.5
print("회귀로 읽으면:", z)               # 1.5 (그대로 예측값)
print("분류로 읽으면:", sigmoid(z))      # 약 0.818 (양성 클래스일 확률)

z를 계산하는 코드는 정확히 한 줄로 똑같고, 그 다음 줄에서 sigmoid()를 씌우느냐 마느냐만 다르다는 걸 눈으로 확인할 수 있다 — 이 챕터가 반복해서 강조하는 “같은 모델, 다른 출력“이 실제 코드 수준에서도 정말로 한 줄 차이라는 뜻이다. Chapter 2에서는 여기서 한 걸음 더 나아가, 이 z를 만드는 \(w, b\) 자체를 데이터로부터 어떻게 학습하는지(경사하강법) 배운다.

지금부터 배우는 거의 모든 알고리즘은 다음 두 단계 틀을 따른다: (1) 모델이 얼마나 틀렸는지를 숫자 하나로 요약하는 손실함수 \(J(w)\)를 정의하고, (2) \(J(w)\)를 최소화하는 \(w\)를 찾는다(대개 경사하강법, Chapter 2). 회귀의 손실함수(평균제곱오차)와 분류의 손실함수(교차 엔트로피)는 형태가 다르지만, “모델의 틀린 정도를 수치화하고 그걸 줄인다“는 구조 자체는 동일하다 — 이 공통 언어 하나가 이번 학기 14개 챕터를 관통하는 뼈대다.

이 두 단계 틀(“손실함수를 정의하고, 그것을 최소화하는 파라미터를 찾는다”)은 사실 이번 학기뿐 아니라 지도학습 전체의 공통 언어다. Chapter 2의 선형회귀·로지스틱회귀부터, Chapter 5의 SVM(힌지 손실), Chapter 9의 신경망(역전파로 손실을 최소화)까지 — 알고리즘마다 \(h\)의 형태(직선? 트리? 신경망?)와 손실함수 \(J\)의 모양은 다르지만, “틀린 정도를 수치화한 뒤 그걸 줄이는 방향으로 파라미터를 옮긴다“는 절차 자체는 똑같이 반복된다. 그래서 이번 학기를 공부하는 가장 효율적인 방법은 매 챕터를 완전히 새로운 것으로 대하기보다, “이 알고리즘의 \(h\)는 무엇이고, \(J\)는 무엇이며, 어떻게 최소화하는가“라는 세 가지 질문을 습관적으로 던지는 것이다 — 1.2절 서두에서 던진 “먼저 문제를 정의하라“는 조언이, 사실은 알고리즘을 배울 때도 그대로 적용되는 셈이다.

자주 하는 실수: 정의를 건너뛰고 바로 알고리즘부터 고르기

실전에서 자주 벌어지는 실패 사례를 구체적으로 짚어보자. 어느 스타트업이 “고객이 이탈할지 예측하는 모델을 만들자“는 목표만 갖고, 곧바로 “그럼 신경망을 쓸까, XGBoost를 쓸까?“부터 논의를 시작했다고 하자. 몇 주 뒤 모델은 완성됐지만 성능이 엉망이었다 — 원인을 되짚어보니, “이탈“의 정의(30일 미접속? 구독 해지? 환불 요청?)조차 팀마다 다르게 이해하고 있었고, 그래서 \(y\)(라벨) 자체가 데이터셋 안에서 일관성 없이 매겨져 있었다. 알고리즘 선택에 쓴 시간보다, \(y\)를 정의하는 데 쓴 시간이 훨씬 적었던 것이 진짜 원인이었다.

이 사례가 주는 교훈은 명확하다 — “어떤 모델이 가장 정확할까“는 프로젝트 중반 이후에나 의미 있는 질문이고, 프로젝트 초반에 가장 먼저 답해야 할 질문은 언제나 “\(x\)는 무엇이고, \(y\)는 정확히 무엇이며, 그 정의에 모두가 동의하는가“이다. 이번 학기 팀 프로젝트(Chapter 8, 16)를 시작할 때도 데이터를 내려받자마자 모델링에 뛰어들지 말고, 이 세 가지 질문에 먼저 팀 전체가 명시적으로 답을 적어두는 것을 권한다.

확인 문제: 이 시나리오는 어떤 갈래인가?

배운 세 갈래 분류를 실제 시나리오에 적용해보는 연습이다 — 각 사례를 읽고 지도/비지도/강화학습 중 무엇인지, 그리고 지도학습이라면 회귀인지 분류인지 스스로 판단해보자(답은 각 문항 바로 아래에 있다. 먼저 스스로 답해본 뒤 확인할 것).

  • (a) 넷플릭스가 사용자 수천 명의 시청 기록(장르, 시청 시간)만 보고 “비슷한 취향을 가진 사용자 그룹“을 자동으로 찾아낸다.

    답: 비지도학습 — 정답 라벨(“이 사람은 그룹 3에 속한다”) 없이 데이터의 구조(비슷한 시청 패턴)만으로 그룹을 찾아내기 때문이다.

  • (b) 은행이 과거 대출자 데이터(소득, 신용점수, 상환 여부)를 보고 “새 신청자가 상환할지 여부“를 예측한다.

    답: 지도학습 · 분류 — 각 과거 대출자에게 “상환함/못함“이라는 범주형 정답이 이미 붙어 있고, 새 데이터의 범주를 예측하는 문제다.

  • (c) 로봇 청소기가 배터리를 아끼면서 방을 최대한 깨끗이 청소하도록, 스스로 수백 번 시행착오를 거치며 움직임 전략을 개선한다.

    답: 강화학습 — “이 방향이 정답이다“라고 알려주는 사람은 없고, “청소된 면적“과 “남은 배터리“라는 보상 신호만으로 스스로 정책을 개선하기 때문이다(ML2에서 본격적으로 다룬다).

  • (d) 부동산 플랫폼이 매물 정보(평수, 위치, 연식)로 예상 거래가를 숫자로 예측한다.

    답: 지도학습 · 회귀 — 예측 대상 \(y\)(거래가)가 범주가 아니라 연속적인 숫자이기 때문이다.

이 네 문항에서 판단의 기준이 항상 같았다는 점에 주목하라 — **“정답 라벨이 있는가 없는가”, 있다면 “그 라벨이 숫자인가 범주인가”**라는 질문 두 개만으로 어떤 문제든 세 갈래 중 하나로, 그리고 지도학습이라면 다시 회귀/분류 중 하나로 분류할 수 있다.
