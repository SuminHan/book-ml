Chapter 13. 로봇 시뮬레이션과 제어 기초 (Robot Simulation & Control Basics)

지금까지 배운 강화학습 알고리즘은 CartPole처럼 단순화된 환경에서 다뤘다. 실제 로봇 — 팔, 다리, 바퀴가 달린 물리적 시스템 — 을 다루려면, “행동이 연속적인 힘/토크“라는 사실뿐 아니라, 그 힘이 실제 물리 법칙(관성, 중력, 마찰)을 거쳐 로봇을 움직인다는 사실까지 감안해야 한다. 이번 장은 Chapter 9~12에서 배운 알고리즘들을 실제로 적용해볼 로봇 시뮬레이션의 기초 개념을 다룬다.

13.1 로봇공학 기초 개념: 상태공간과 운동학

로봇의 상태는 보통 각 관절의 각도와 각속도로 표현된다 — 2관절 로봇 팔이라면 상태는 \((\theta_1, \theta_2, \dot\theta_1, \dot\theta_2)\)처럼 4차원 벡터가 된다. 정기구학(forward kinematics)은 이 관절 각도들로부터 팔 끝(end-effector)의 실제 위치를 계산하는 것이고, 역기구학(inverse kinematics)은 그 반대 — “팔 끝을 이 위치로 보내려면 관절 각도가 얼마여야 하는가“를 계산하는 것이다. 이런 기하학 계산은 로봇공학 자체의 깊은 주제이지만, 강화학습 관점에서 중요한 것은 단 하나다: 상태와 행동이 이제 물리적으로 의미 있는 연속값이라는 것이다 — Chapter 3.1에서 배운 MDP의 \(\mathcal{S}, \mathcal{A}\)가 이제 추상적인 기호가 아니라 실제 각도·힘의 단위를 갖는다.

13.2 시뮬레이션이 필요한 이유: sim-to-real

실물 로봇으로 강화학습을 직접 학습시키면 몇 가지 현실적인 문제에 부딪힌다 — 수만 번의 시행착오 동안 로봇이 고장 나거나, 사람에게 위험할 수 있고, 무엇보다 느리다(물리 세계는 컴퓨터 시뮬레이션보다 훨씬 느리게 흐른다). 그래서 실전에서는 먼저 물리 엔진 위의 시뮬레이션에서 정책을 학습시킨 뒤, 그 정책을 실물 로봇으로 옮긴다 — 이 전이 과정을 sim-to-real이라 부른다.

문제는 시뮬레이션이 실제 물리를 완벽히 재현하지 못한다는 것이다(마찰 계수, 센서 잡음, 재질의 미세한 차이 등) — 시뮬레이션에서만 잘 작동하고 실물에서는 실패하는 정책을 현실 격차(reality gap)라 부른다. 이 격차를 줄이는 대표적인 방법이 도메인 무작위화(domain randomization) — 시뮬레이션의 물리 파라미터(마찰, 질량, 조명 등)를 매 학습 에피소드마다 무작위로 바꿔가며 학습시키는 것이다. 정책이 하나의 고정된 시뮬레이션 설정이 아니라 “다양한 물리 조건 전체“에 대해 잘 작동하도록 강제하면, 그중 어느 하나(실물 로봇의 실제 물리 조건)에도 더 잘 일반화하는 경향이 생긴다 — Chapter 6(ML1)에서 배운 정규화가 “모델을 덜 유연하게 만들어 분산을 줄인다“는 것과 비슷하게, 여기서는 “환경 자체를 다양화해서 정책이 특정 시뮬레이션 설정에 과적합하지 않게 만든다.”

13.3 Gymnasium/PyBullet 로봇 환경

이번 학기 실습은 Gymnasium이 제공하는 로봇류 환경으로 진행한다 — 이미 Chapter 1과 9에서 쓴 CartPole·Pendulum도 사실 아주 단순화된 “로봇 제어” 문제다(막대의 균형을 잡는 것, 진자를 세우는 것 모두 관절 제어의 가장 작은 형태다). 좀 더 로봇에 가까운 연속 제어 문제로 넘어가 보자:

import gymnasium as gym
import numpy as np

env = gym.make("Pendulum-v1")  # 연속 행동공간을 가진 가장 단순한 "관절 제어" 문제
obs, info = env.reset(seed=0)
print("상태(cos theta, sin theta, 각속도):", obs)
print("행동공간:", env.action_space)  # Box(-2.0, 2.0, (1,)) -- 연속값 토크

# 손으로 설계한 간단한 PD(비례-미분) 제어기: 각도가 클수록, 각속도가 클수록 반대로 힘을 준다
total_reward = 0.0
for _ in range(50):
    cos_th, sin_th, thdot = obs
    theta = np.arctan2(sin_th, cos_th)
    action = np.clip(-2.0 * theta - 0.5 * thdot, -2.0, 2.0)
    obs, reward, terminated, truncated, info = env.step([action])
    total_reward += reward
print("PD 제어기의 50스텝 누적 보상:", round(total_reward, 2))
env.close()

이 PD(Proportional-Derivative) 제어기는 강화학습이 전혀 아니다 — 사람이 직접 설계한 규칙일 뿐이다. 그런데도 무작위 행동보다 훨씬 나은 성능을 낸다(무작위 정책의 50스텝 누적 보상은 보통 -1200~-1600 근처인데, 이 간단한 규칙은 -240 근처까지 개선된다). 이 비교가 보여주는 것: 강화학습의 목표는 이런 손으로 설계한 제어기보다 더 나은, 또는 사람이 규칙으로 설계하기 어려운 상황에서도 작동하는 정책을 데이터로부터 직접 찾아내는 것이다.

13.4 연속제어에 PPO 적용하기

Chapter 11의 PPO는 이산 행동(softmax 정책)뿐 아니라 연속 행동에도 자연스럽게 확장된다 — 신경망이 각 행동 차원마다 정규분포의 평균과 표준편차를 출력하도록 하면 된다:

\[\pi_\theta(a|s) = \mathcal{N}(a; \mu_\theta(s), \sigma_\theta(s)^2)\]

로그 확률 \(\log \pi_\theta(a|s)\)은 정규분포의 확률밀도함수에서 바로 계산되며, Chapter 10.4의 로그미분 트릭과 Chapter 11의 클리핑 목적함수는 이산/연속 여부와 무관하게 형태가 그대로 유지된다 — “행동을 어떻게 파라미터화하는가“만 바뀔 뿐, 그 뒤의 최적화 기계는 동일하다는 것이 정책기반 방법의 큰 장점이다.

import math

def gaussian_log_prob(action, mu, sigma):
    # 연속 행동에 대한 로그 확률 -- softmax 대신 정규분포를 쓴다는 점만 다르다
    return -0.5 * math.log(2 * math.pi * sigma**2) - (action - mu)**2 / (2 * sigma**2)

로봇 시뮬레이션은 지금까지 배운 알고리즘(DQN, PPO)을 “실제 물리 법칙이 지배하는 연속 행동공간“이라는 더 현실적인 무대로 옮기는 시험대다 — 다음 장에서는 이 시뮬레이션을 더 정교한 물리엔진으로, 그리고 대규모 GPU 가속 환경으로 확장한다.
