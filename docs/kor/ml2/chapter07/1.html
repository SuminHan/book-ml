7.1 n-step TD: MC와 TD(0) 사이의 다이얼

복습: 두 극단 — MC와 TD(0)

Chapter 5의 몬테카를로(MC)와 Chapter 6의 TD(0)는 “상태 가치 \(V(s)\)의 목표값으로 무엇을 쓸 것인가“라는 질문의 서로 다른 답이었다. MC의 목표값은 에피소드 끝까지의 실제 보상 합(실제 리턴) \(G_t\)이었고, TD(0)의 목표값은 \(r + \gamma V(s’)\)(1 스텝의 실제 보상 + 나머지는 추정치)였다. 이 두 목표값을 나란히 놓고 쓰면, 사실 같은 구조의 다른 길이라는 게 보인다:

  • TD(0): \(r_t + \gamma V(s_{t+1})\) — 실제 보상 \(1\)개 + 추정치
  • MC: \(r_t + \gamma r_{t+1} + \gamma^2 r_{t+2} + \cdots\) — 실제 보상을 끝까지 전부 + 추정치 없음

즉, 차이는 “실제 보상을 몇 개 쓸 것인가“가 1개와 “끝까지 전부” 의 차이일 뿐이다. 그런데 1개와 “끝까지” 사이의 아무 정수도 가능해야 한다 — \(n\)개의 실제 보상 합 + 나머지 부분은 추정치, 라는 목표값을 쓰자. 이것이 n-step TD1 2다.

n-step TD: MC와 TD(0) 사이의 다이얼

TD(0)의 목표값은 \(r + \gamma V(s’)\)(1 스텝의 실제 보상 + 나머지는 추정치)였다. 이걸 일반화해서, \(n\) 스텝만큼 실제로 관찰한 보상을 쓰고 그 이후는 추정치로 대체하면:

\[G_t^{(n)} = R_t + \gamma R_{t+1} + \cdots + \gamma^{n-1} R_{t+n-1} + \gamma^n V(s_{t+n})\]

\(n=1\)이면 정확히 TD(0)이고, \(n \to \infty\)(에피소드 끝까지)이면 정확히 몬테카를로다. \(n\)을 늘릴수록 실제 관찰에 더 의존하게 되어 편향은 줄고 분산은 커진다(Chapter 6.1의 표에서 본 그 트레이드오프의 연속선상에 있다) — \(n\)은 그 사이 어딘가에서 상황에 맞게 고르는 하이퍼파라미터다.

정리하면:

\(n\)실제 보상추정치(부트스트래핑)갱신
TD(0)1\(R_t\) 1개\(V(s_{t+1})\)매 스텝 즉시
n-step TD\(n\)\(R_t, \dots, R_{t+n-1}\) \(n\)개\(V(s_{t+n})\)매 스텝(첫 갱신은 \(n-1\) 스텝 지연)
MC\(\infty\)끝까지 전부없음에피소드 종료 시

여기서 한 가지 기다려야 하는 시간이 생긴다는 점에 주목하라. \(G_t^{(n)}\)의 목표값을 계산하려면 \(t\)에서 \(t+n-1\)까지의 보상이 다 모이어야 하므로, \(t\)번 상태의 첫 갱신은 최소 \(n-1\) 스텝이 지나서야 가능해진다. \(n=1\)이면 매 스텝 즉시 갱신했던 TD(0)와 달리, \(n\)이 클수록 “학습의 시차“가 커진다. 이 시차가 갱신 횟수에는 영향을 주지 않는다는 점(아래 FAQ에서 확인)은 반직관적이므로, 실습에서 직접 세어보자.

코드로 보는 n-step TD

7개 상태 random walk(상태 0과 6이 터미널, \(1\sim5\)가 이동 상태, 매 스텝 50:50으로 좌우 이동, 왼쪽 끝에 \(-1\)·오른쪽 끝에 \(+1\) 보상, \(\gamma = 0.9\), 중간 상태 3에서 시작) 위에서 \(n\)을 바꿔가며 학습하는 함수다:

import random

def env_step(s, a):
    """random walk 환경. a: 0=left, 1=right (무작위 정책이라 a는 무시)."""
    ns = s + (1 if random.random() < 0.5 else -1)
    if ns == 0:
        return 0, -1.0, True   # 왼쪽 끝 도착: 보상 -1, 종료
    if ns == 6:
        return 6, 1.0, True    # 오른쪽 끝 도착: 보상 +1, 종료
    return ns, 0.0, False

def n_step_td(env_step, n, n_episodes, alpha, gamma, n_states, start_state):
    V = [0.0] * n_states
    for _ in range(n_episodes):
        states, rewards = [start_state], []
        s, T, t = start_state, float('inf'), 0
        while True:
            if t < T:
                a = random.randrange(2)  # 데모용 무작위 정책
                ns, r, done = env_step(s, a)
                states.append(ns)
                rewards.append(r)
                if done:
                    T = t + 1
                s = ns
            tau = t - n + 1  # tau번째 상태를 지금 갱신
            if tau >= 0:
                G = sum(gamma ** (i - tau) * rewards[i]
                        for i in range(tau, min(tau + n, len(rewards))))
                if tau + n < T:
                    G += gamma ** n * V[states[tau + n]]
                V[states[tau]] += alpha * (G - V[states[tau]])
            if tau == T - 1:
                break
            t += 1
    return V

세 부품을 따로 뜯어보자.

tau는 왜 현재 시점보다 \(n-1\)만큼 뒤처지는가. tau(갱신 대상 시점)가 항상 현재 시점보다 \(n-1\)만큼 뒤처져 있다는 점에 주목하라 — \(n\) 스텝만큼의 실제 보상이 다 모여야 그 목표값을 계산할 수 있기 때문이다. t가 한 스텝씩 앞으로 갈 때마다, “갱신할 차례인” 상태 tau도 한 칸씩 앞으로 밀려나간다. 에피소드가 끝난 뒤(t >= T)에도 이 밀림이 tau == T-1이 될 때까지 계속되는 이유도 바로 이것이다 — 아직 \(n\) 스텝의 목표값을 계산 못 한 상태가 남아 있어서다.

중요: 목표값의 할인 지수를 세어라. \(G_t^{(n)}\)의 정의에서 \(R_{t+k}\)의 지수는 \(k\)다. tau번 상태를 갱신할 때 rewards[tau](= \(R_{tau}\))의 지수는 \(0\), rewards[tau+1](= \(R_{tau+1}\))의 지수는 \(1\), …, 즉 rewards[i]의 지수는 \(i - tau\)다. 여기서 하나만 틀리(gamma ** (i - tau - 1)처럼) 쓰면, 각 보상이 \(\gamma^{-1}\)만큼 덜 할인된 — 곧 편향된 — 목표값이 만들어져 \(n=1\)일 때조차 TD(0)의 목표값이 아니게 된다. 실제로 위 함수의 보상 가중치를 i - tau - 1로 쓰면, \(n=1\)이면서 2000 에피소드 학습 후에도 \(V(5) \approx 0.84\)로 참값 \(+0.5643\)에서 크게 벗어나 수렴하지 않는다. 지수 하나가 틀리면 “TD(0)를 쓰는 것“이 아니라 “편향된 목표값을 끝없이 쓰는 것“이 되는 셈이다 — 확인 문제 3에서 이 버그를 의도적으로 넣었다 빼면서 직접 확인해볼 수 있다.

tau + n < T 분기 — “에피소드가 윈도우 안에 끝났는가”. \(tau + n < T\)이면(\(n\) 스텝 윈도우가 끝나기 전에 에피소드가 끝나지 않았다면) 목표값에 \(\gamma^n V(s_{tau+n})\)를 더한다. \(tau + n \ge T\)이면(에피소드가 그 안에 끝났다) 보상이 다 모이지 못해 추정치 항을 생략하고, 실제로 모은 보상분만 쓴다 (보상 합을 계산하는 min(tau + n, len(rewards))가 이 절단을 처리한다). 이 “끝에서 추정치 절단” 덕분에, \(n\)이 에피소드 길이보다 길면 n-step TD는 자동으로 MC가 된다 — 실습에서 n=50이 사실상 MC로 동작하는 이유가 이것이다(이 환경의 에피소드 길이는 보통 50보다 짧으므로).

참값은 얼마인가. 이 random walk의 참값 \(V^\pi(s)\)는 벨만방정식(상태 1~5가 미지수인 연립 일차방정식, 연습문제 2에서 직접 풀어보자)으로 정확히 구할 수 있다:

\[V^* = [0,\; -0.5643,\; -0.2539,\; 0,\; +0.2539,\; +0.5643,\; 0]\]

대칭성(좌우가 미러링) 때문에 \(V(3) = 0\), \(V(2) = -V(4)\), \(V(1) = -V(5)\)가 성립한다. 7개 상태 random walk에서 n=3으로 10 에피소드 학습(\(\alpha = 0.1\), seed 고정)시켜 보면, 이 참값의 모양을 대략 따라가며 목표(오른쪽 끝, +1)에 가까운 상태일수록 가치가 매끄럽게 커지는 것을 확인할 수 있다(예: 상태 1에서 \(-0.48\) 근처에서 오른쪽으로 갈수록 상태 5에서 \(+0.37\) 근처까지 단조 증가). 에피소드가 10개뿐이라 참값까지 다 도달하진 않지만, 방향(오른쪽이 왼쪽보다 가치가 높다)은 이미 잡혀 있는 상태다.

online 관점 vs forward 관점

위 코드를 online 관점(online view)이라고 한다 — 학습이 진행되면서 목표를 만들어 갱신하는 방식. “지금 \(t\) 스텝을 왔다“고 할 때, 지금까지 실제로 쌓인 \(R_t, \dots, R_{t+n-1}\) 을 모아 \(G_t^{(n)}\)을 계산한다. 위 코드의 tau = t - n + 1 과 tau + n < T 분기가 바로 online 관점의 산물이다.

반면 forward 관점(forward view)은, “어떤 \(n\)을 쓰느냐“가 같은 경험 위에서 서로 다른 목표값을 만들어내는 것을 시간축을 앞에서 뒤로 읽는 관점으로 기술한다. 같은 trajectory가 주어졌을 때, \(n=1\)의 목표는 \(R_t + \gamma V(s_{t+1})\), \(n=2\)의 목표는 \(R_t + \gamma R_{t+1} + \gamma^2 V(s_{t+2})\)로, 같은 경험에서 다른 목표가 생긴다.

왜 두 관점을 둘 다 아는 것이 좋은가?

  1. online 관점은 실제 알고리즘의 실행 순서(갱신 시차, 에피소드 끝 처리)를 정확히 반영한다.
  2. forward 관점은 “n이 커지면 MC에 가까워진다“는 직관 (목표값의 정의 자체에서 \(n \to \infty\)가 MC의 리턴이 됨)를 가장 투명하게 보여준다.

두 관점이 동일한 학습 알고리즘을 기술한다는 사실은, 7.2절의 적격흔적이 “모든 \(n\)을 동시에” 쓰는 기법으로 이어서 설명할 때 핵심이 된다 — 적격흔적은 forward 관점에서 “n별로 다른 목표“를 한 번의 실제 경험 위에서 가중합으로 만들어주는 기계다. 이번 절에서는 online 관점 코드를 중심으로 하고, forward 관점은 “왜 n이 커지면 편향은 줄고 분산은 커지는가“를 설명할 때 쓴다.

왜 \(n\)이 커지면 편향은 줄고 분산은 커지는가

\(V\)가 이미 참값 \(V^\pi\)라면, \(G_t^{(n)}\)의 기대값은 정확히 \(V^\pi(s_t)\)다 — 실제 보상 합이 “앞으로 받을 할인된 보상의 기댓값“의 단일 샘플이기 때문이다(어떤 \(n\)에서든 이것은 성립한다). 그런데 학습 초반의 \(V\)는 참값과 다르다. 목표값에 추정치 \(V(s_{t+n})\)가 일부 섞여 있다는 것 — 이것이 **편향(bias)**의 출처다. \(n\)이 커질수록 목표값에서 추정치 비중이 줄고 실제 보상 비중이 커지므로, \(V\)가 부정확해도 목표값이 참값에 더 가까워진다(편향 감소). 대신, 실제 보상의 합이 길어질수록 각 스텝의 전이·보상 확률이라는 무작위성이 더 많이 누적되어 목표값의 **분산(variance)**은 커진다 — MC가 “분산 극대“인 이유와 정확히 같다.

이 트레이드오프가 숫자로 어떻게 나타나는지 위 random walk에서 확인해보자. 각 \(n \in \{1, 3, 5, 10, 50\}\)으로 10 에피소드 학습(\(\alpha = 0.1, \gamma = 0.9\))을 30개 seed로 반복해 평균하고, 추정값과 참값의 RMS 오차를 구하면:

n=1 :  RMS 0.4007   (TD(0))
n=3 :  RMS 0.3061   <- 이 환경·예산에서 최적
n=5 :  RMS 0.3493
n=10:  RMS 0.3994
n=50:  RMS 0.4170   (사실상 MC)

오차가 \(n\)에 대해 U자 모양이다 — 양 극단(\(n=1\), \(n=50\))보다 중간 어딘가(\(n=3\))가 가장 낮은 오차를 보인다. \(n=1\)(TD(0))은 매 스텝 즉시 갱신하지만 추정치에 크게 의존해서(편향), 겨우 10 에피소드로는 그 편향을 다 씻어낼 시간이 부족하다. \(n=50\)(사실상 MC에 가깝다, 에피소드 길이가 보통 그보다 짧으므로)은 편향은 없지만 각 갱신에 담긴 무작위성(분산)이 너무 커서, 적은 에피소드로는 오히려 불안정하다. 그 사이 어딘가(\(n=3\))가 이번 실험에서는 최적이었다 — 실전에서 \(n\)을 몇으로 잡을지는 이렇게 데이터로 확인해야 하는 하이퍼파라미터라는 것, 즉 ML1 Chapter 4.1에서 본 편향-분산 트레이드오프가 여기서 U자 곡선이라는 구체적인 숫자로 다시 확인되는 셈이다.

그림의 두 패널을 비교할 것. 에피소드 10개(좌)에서는 \(n=3\)이 두드러지게 가장 낮지만, 에피소드 500개(우)로 늘리면 최저점이 \(n=1\) 쪽으로 이동한다(\(n=1\): 0.268, \(n=3\): 0.336, \(n=50\): 0.457) — 데이터가 쌓일수록 “갱신이 잦고 분산이 작은” TD(0) 쪽의 이점이 살아나기 때문이다. 한편 큰 \(n\)(\(n=50\)) 쪽 패널티는 예산이 커져도 크게 줄지 않는다. 결론: “보편적인 최적 n“은 없다 — 최적 n은 에피소드 예산·환경의 확률적 정도·할인율에 따라 움직이는 하이퍼파라미터다. 이것이 실전에서 n을 검증으로 튜닝해야 하는 이유이며, 7.2절의 적격흔적이 “n을 고르는 문제” 자체를 피(모든 n을 흔적으로 가중합)하는 대안인 이유이기도 하다.3

\(n\)을 고르는 경험칙. (i) 에피소드가 짧고 경험 횟수가 많다면 \(n = \infty\)(MC)나 작은 \(n\)(TD(0))이 안전하다 — 편향을 씻어낼 데이터가 있으므로. (ii) 에피소드가 길고 경험 횟수가 적다면 중간 \(n\)(3~10)이 편향을 줄이면서 분산을 관리해 준다. (iii) 에피소드가 끝이 없다(continuing task)면 MC 자체가 불가능하므로 유한 \(n\) 또는 적격흔적 (7.2절)을 쓴다. 실전 DQN4 계열 알고리즘(Chapter 9)에서도 n-step 리턴은 기본 옵션으로 제공되며, 보통 3~10 범위로 튜닝한다.

자주 하는 실수

  • 보상 합산의 할인 지수를 잘못 세는 것. 앞선 “중요: 목표값의 할인 지수를 세어라“에서 본 문제다. i - tau - 1로 쓰면 \(n=1\)일 때조차 TD(0)가 아닌 편향된 목표값을 쓰게 되고, 2000 에피소드 학습 후에도 참값에 도달하지 않는다. “왜 안 수렴하지?“라고 느끼면 먼저 이 지수를 확인하라.
  • tau = t(지금 상태를 지금 갱신)로 쓰는 것. \(t\)번 상태의 목표값 \(G_t^{(n)}\)은 \(R_t, \dots, R_{t+n-1}\)이 다 모인 시점, 즉 t + n - 1에야 계산된다. tau = t로 쓰면 아직 모이지 않은 보상을 참조해서 인덱스 에러가 나거나, 0으로 채워져 편향된 목표값이 된다. tau = t - n + 1이 정확한 표현이다.
  • 보상 합이 \(n\)개를 넘지 않는지 안 확인하는 것. 에피소드 중간이 아니라 끝 근처에서는 실제로 남은 보상이 \(n\)개보다 적다(예: \(n=3\)인데 2스텝 남음). min(tau + n, len(rewards))로 상한을 안 걸면 인덱스 에러가 나거나, “없는 보상“을 0으로 처리해 목표값이 틀어진다. 같은 정신으로, 추정치 항도 tau + n < T 조건이 없으면 에피소드가 이미 끝난 뒤에 \(V\)을 더하는(또는 존재하지 않는 인덱스를 참조하는) 오류가 생긴다.
  • “\(n\)을 에피소드 길이보다 크게 하면 갱신이 안 된다“고 오해하는 것. 갱신은 에피소드당 모든 이동 상태(\(0 \le \tau \le T-1\))마다 정확히 한 번씩 일어난다 — \(n\)이 길어도 에피소드 종료 직후의 “꼬리 갱신”(보상이 \(n\)개 모이지 못한 절단 목표값)으로 처리되기 때문이다(코드에서 t >= T 구간이 tau == T-1까지 계속되는 이유). \(n\)이 바꾸는 것은 갱신 횟수가 아니라, 첫 갱신까지의 시차와 목표값의 구성(실제/추정 비율)이다.
  • “이 환경에서 n=3이 최적이었다“고 일반화하는 것. U자 곡선의 최저점은 에피소드 예산·환경에 따라 움직인다(위 그림에서 10 에피소드 → n=3, 500 에피소드 → n=1). 실전에서는 n을 검증 데이터로 튜닝하는 것이 표준이며, 7.2절의 적격흔적은 이 튜닝 자체를 줄이는 방향의 대안이다.

실습: n을 바꿔가며 random walk에서 최적 지점 찾기

7.1절의 U-자 곡선을 직접 만들어보자. 같은 random walk 환경에서 \(n \in \{1, 3, 5, 10, 50\}\)으로 각각 10 에피소드 학습(\(\alpha = 0.1, \gamma = 0.9\), 30 seed 평균)을 하고 RMS 오차를 비교하면, 위 표와 그림의 좌측 패널과 같은 U자 곡선이 재현된다(최저점 n=3, RMS 0.3061).

추가 과제: 에피소드 예산도 바꿔보기. 에피소드 수를 10에서 500으로 늘려 다시 그리면, 위 그림의 우측 패널처럼 최저점이 \(n=1\) 쪽으로 이동한다. 이 결과를 보고 “실전에서 n을 고를 때 어떤 상황을 고려해야 하는가“를 한 문장으로 설명해보자. (힌트: 에피소드 예산이 적을 때 와 많을 때, U자 곡선의 최저점 위치가 어떻게 달라지는가? 그게 왜 그런가?)

확인 문제

  1. \(n=1\)이 정확히 TD(0)임을 코드로 확인. n_step_td에서 n=1로 실행하고, 갱신에 쓰이는 G가 \(R_{tau} + \gamma V(s_{tau+1})\)(TD(0)의 목표값)와 동일한지 손으로 한 스텝 추적해서 확인하라. (힌트: tau + 1 < T일 때만 추정치 항이 추가된다. 에피소드 마지막 스텝에서는 추정치 항이 없어 \(G = R_{tau}\)만 된다 — 이것이 “터미널 상태의 V는 0“과 일치하는지 생각해보라.)
  2. \(n \to \infty\)가 MC임을 확인. 에피소드가 길이 \(T\)에서 끝난다고 할 때(\(V(s_T) = 0\)), \(n \ge T\)인 n-step TD의 \(t\)번 상태 목표값이 실제 리턴 \(G_t = \sum_{k=0}^{T-t-1} \gamma^k R_{t+k}\)와 동일한지 보여라.
  3. 보상 가중치 버그의 효과. n_step_td에서 gamma ** (i - tau)를 gamma ** (i - tau - 1)로 바꾸고, n=1로 2000 에피소드 학습하면 참값 \([0, -0.56, -0.25, 0, +0.25, +0.56, 0]\)에 도달하지 못함을 확인하라. 이 버그가 “목표값의 편향이 수렴 고정점 자체를 바꾼다“는 점을 어떻게 보여주는지 한 문장으로 설명하라.
  4. 갱신 횟수 세기. 에피소드 길이가 \(T\)일 때, \(n = 1\)과 \(n = 3\)과 \(n = T + 1\)인 n-step TD 각각에서 그 에피소드 중 몇 번의 갱신이 일어나는지 코드를 추적해서 세어라. (힌트: tau가 어떤 범위까지 갱신되고, 언제 break하는가? 세 경우에 갱신 횟수가 모두 같은가?)

자주 묻는 질문

Q. n-step TD도 부트스트래핑인가요? 그렇다 — \(n\)이 유한하기만 하면(\(n<\infty\)) 목표값 \(G_t^{(n)}\)에 여전히 추정치 \(V(s_{t+n})\)이 들어 있으므로 부트스트래핑이다. \(n\to\infty\)일 때만(에피소드가 끝날 때까지 실제 보상만 쓸 때) 부트스트래핑이 완전히 사라지고 순수 MC가 된다.

Q. 실전에서는 n을 얼마로 쓰나요? 문제와 데이터양에 따라 다르며, 보통 몇 개(4~10 정도)의 후보를 검증 성능으로 비교해서 고른다 — 이 절의 실습이 바로 그 튜닝 과정의 축소판이다. Chapter 9의 DQN 계열 알고리즘 중에는 n-step 리턴을 기본 옵션으로 제공하는 구현도 많다. (경험 재현 버퍼를 쓰는 DQN은 버퍼에서 미니배치를 무작위로 뽑으므로, “시간적으로 \(n\) 스텝 앞“의 경험을 버퍼에서 이어붙여 n-step 목표값을 만들 수도 있다 — 이 변형은 Chapter 9 실습에서 마주칠 수 있다.)

Q. n-step TD의 에피소드당 갱신 횟수는 TD(0)와 MC와 어떻게 다른가? 같다 — 이동 상태가 \(T\)개인 에피소드에서, TD(0)도 n-step TD도 각 상태마다 정확히 한 번씩(총 \(T\)번) 갱신한다. n-step TD에서 첫 \(n-1\) 상태는 “갱신이 늦어지는” 뿐이지(\(n-1\) 스텝 뒤에 갱신) 사라지지 않으며, 에피소드가 끝난 뒤에도 tau == T-1이 될 때까지 꼬리 갱신이 이어진다. \(n\)이 바꾸는 것은 갱신 횟수가 아니라, 첫 갱신까지의 시차와 목표값의 구성(실제 보상 \(n\)개 + 추정치 vs 실제 보상 1개 + 추정치)이다. MC는 (첫방문 기준) 에피소드가 끝난 뒤에 각 상태를 한 번씩 갱신한다는 점에서 갱신 시점이 다르다.

Q. n이 클수록 목표값의 분산이 커진다는 건, “갱신당 변동“이 크다는 뜻인가요? 그렇다 — 같은 \(V\) 기준으로 보아, 목표값 \(G_t^{(n)}\)이 실현값마다 흔들리는 폭이 \(n\)에 따라 달라진다. \(n=1\)이면 한 스텝의 전이 무작위성만 반영되고, \(n\)이 커지면 \(n\) 스텝치의 전이·보상 무작위성이 합쳐진다(보상이 0인 스텝이 많아도 전이의 무작위성은 누적된다 — 이 random walk에서는 보상 0의 스텝도 “어디로 갔는가“에 따라 이후 경로가 달라지므로). 같은 총 “정보“를 작은 덩어리(잦은 갱신)로 나누어 갱신하는 것 과 큰 덩어리(드물지만 큰 갱신)로 나누는 것의 차이는, ML1 Chapter 9에서 본 배치 크기 트레이드오프(작은 배치는 경사가 노이져스하지만 갱신이 잦고, 큰 배치는 매 갱신이 안정적)와 같은 구조다.

Q. n-step TD와 적격흔적(7.2절)은 정말 같은 것을 계산하는가? “같은 것을 계산한다“기보다는, “같은 효과 (모든 n을 가중합)를 다른 순서로 만든다“가 정확하다. n-step TD는 n을 하나 고정해 그 하나의 목표값으로 갱신하고, 적격흔적은 한 번의 경험에서 모든 n의 목표값을 가중합으로 만들어 동시에 갱신한다. \(\lambda\)는 “어떤 n에 얼마만큼 가중치를 두느냐“를 조절하는 다이얼이 되며, 7.2절에서 “전방 관점과 후방 관점의 등가성“으로 이 연결을 다룬다.
