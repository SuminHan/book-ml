Machine Learning 1/2 (한국어)

4.3 가치 반복, 수렴 증명, 그리고 모델 기반이라는 전제

가치 반복

가치 반복(Value Iteration)은 정책평가와 정책개선을 합쳐서, 정책평가를 끝까지 수렴시키지 않고 딱 한 번만 하고 바로 개선하는 것을 매 스텝 반복한다 — 벨만 최적방정식 자체를 반복 대입으로 직접 푸는 것과 같다:

def value_iteration(P, R, n_actions, gamma, theta=1e-6):
    n_states = len(P)
    V = [0.0] * n_states
    while True:
        delta = 0
        for s in range(n_states):
            v_new = max(R[s][a] + gamma * sum(prob * V[next_s] for prob, next_s in P[s][a])
                        for a in range(n_actions))
            delta = max(delta, abs(v_new - V[s]))
            V[s] = v_new
        if delta < theta:
            break
    policy = [max(range(n_actions),
                  key=lambda a: R[s][a] + gamma * sum(prob * V[next_s] for prob, next_s in P[s][a]))
              for s in range(n_states)]
    return V, policy

이 코드에서 눈여겨볼 것은, policy_evaluation(4.1절)과 딱 한 줄이 다르다는 것이다 — a = policy[s]로 고른 한 행동이 아니라 max_a [...]로 각 상태에서 가장 좋은 행동을 그때그때 골라버린 것이다. 그뿐이다. 이 “한 줄“이 “주어진 정책을 평가한다“는 문제와 “최적인 정책을 찾는다“는 문제를 가르는 전부이며, 4.1절이 도입한 벨만 연산자의 관점에서는 더 명확해진다: 정책평가는 \(V \xrightarrow{T^\pi} \cdots\)로 **정책 연산자 \(T^\pi\)**를 반복하는 것인 데 반해, 가치반복은 최적 연산자

\[T^* V(s) = \max_a \left[R(s,a) + \gamma \sum_{s’} P(s’|s,a)\, V(s’)\right]\]

을 반복하는 것(\(V \xrightarrow{T^*} V_1 \xrightarrow{T^*} V_2 \to V^*\))이다. 둘은 4.1절의 벨만방정식 2×2 표에서 “기대” 열과 “최적” 열의 차이에 해당한다.

“\(T^*\)를 \(k\)번 적용 = \(k\)스텝만 내다보기”

이 반복이 “매 스텝마다 한 스텝 더 내다보는 것“이라는 직관을 숫자로 확인해보자. 위에서 본 5칸 GridWorld(칸 0~4, 칸 4가 목표, 걸음마다 \(-1\), \(\gamma = 0.9\))에서 \(V_0 = [0,0,0,0,0]\)로 시작해 \(T^*\)를 한 번씩만 적용(synchronous, 한 sweep을 다 끝낸 뒤 갱신)해가면:

\(k\)\(V_k(0)\)\(V_k(1)\)\(V_k(2)\)\(V_k(3)\)\(V_k(4)\)
00.0000.0000.0000.0000.000
1-1.000-1.000-1.000-1.0000.000
2-1.900-1.900-1.900-1.0000.000
3-2.710-2.710-1.900-1.0000.000
4-3.439-2.710-1.900-1.0000.000
5-3.439-2.710-1.900-1.0000.000

\(k\)스텝까지의 최적 리턴. \(V_k(s)\)을 해석하면, “상태 \(s\)에서 출발해 정확히 \(k\)스텝만 최적으로 행동할 때의(그 이후의 보상은 0으로 치는) 할인 누적 보상“이 된다.

  • \(V_1(s)\)는 “한 걸음만 갈 때“의 가치 — 어디에서 시작하든 바로 목표(칸 4)가 아니면 한 걸음에 \(-1\)이므로 전부 \(-1\)이다 (칸 4는 0).
  • \(V_2(s)\)는 “두 걸음까지 볼 때” — 칸 0,1,2는 두 걸음 안에 목표에 못 닿아 \(-1 - 0.9 = -1.9\), 칸 3은 한 걸음이면 목표라 \(-1\)이다.
  • \(V_3(s)\)에서 칸 0은 여전히 세 걸음 안에 못 닿아 \(-1 - 0.9 - 0.81 = -2.71\).

이 “보이는 지평선(horizon)이 매 스텝 한 칸씩 오른쪽으로 넓어진다“는 그림이, 4.1절의 “정보는 한 sweep에 한 칸 전파된다“와 정확히 같은 현상이다. \(k = 4\)가 되면 칸 0에서도 목표까지의 거리(4칸)를 다 보게 되어, 칸 0부터 왼쪽으로 값이 고정되기 시작한다(\(-3.439\) = \(-1 - 0.9 - 0.81 - 0.729\)). 그리고 \(k=4\)에서 더 이상 변하지 않는다 — 이 GridWorld에서 목표까지의 최장 거리가 4이므로, “4스텝만” 보는 것과 “무한히” 보는 것이 같은 답이기 때문이다.

이 직관이 중요한 이유는 두 가지다. 첫째, \(k\)가 충분히 크면 \(V_k\)가 \(V^*\)에 수렴한다는 것이 “왜“이 아니라 “몇 스텝이면“의 눈금자를 준다 — 목표까지의 최대 거리(이 예에선 4)와, 할인이 \(\gamma^k\)로 충분히 작아질 때까지의 \(k\)가 그 상한이다. 둘째, “한 번에 내다보는 스텝 수를 늘려가며 근사한다“는 관점은 Chapter 14의 **모델 기반 강화학습(MPC, Model Predictive Control)**과 동일한 사상이다 — MPC는 매 결정 시점에 “앞으로 \(k\)스텝만” 내다보며 최적 행동을 고르고, \(k\)(예측 지평, prediction horizon)를 키울수록 장기 계획을 더 잘 반영한다. 가치 반복은 그 \(k\)를 스스로 점점 키워가면서 \(k=\infty\)(= \(V^*\))까지 닫아가는 절차인 셈이다.

실습: 정책반복과 가치반복의 수렴 속도 비교하기

같은 5칸 GridWorld에 가치반복을 돌려서, 정책반복과 결과·수렴 속도를 비교해보자:

V_vi, policy_vi = value_iteration(P, R, n_actions, gamma)

V = [-3.439, -2.710, -1.900, -1.000, 0.000]   # 정책반복과 완전히 동일
policy = [1, 1, 1, 1, 0]                       # 정책반복과 완전히 동일
반복 횟수: 5

두 알고리즘 모두 정확히 같은 \(V^*\)와 최적 정책에 도달한다 — 당연한 결과다, 둘 다 4.1절의 벨만 최적방정식이라는 같은 고정점을 찾아가기 때문이다(4.3절에서 이 고정점이 유일함을 증명한다). 다만 “수렴까지 걸리는 계산“의 성격이 다르다 — 이 예시에서 정책반복은 바깥 반복 2번(그 안에 내부 정책평가 sweep 총 10번)이 걸렸고, 가치반복은 단일 반복 루프로 5번 만에 끝났다. 일반적으로 정책반복은 바깥 반복 횟수 자체는 적지만 각 반복(정책평가)이 여러 sweep을 필요로 하고, 가치반복은 매 반복이 가볍지만 대신 반복 횟수가 더 필요할 수 있다 — 상태·행동 공간의 크기와 구조에 따라 어느 쪽이 총 계산량이 더 적을지는 문제마다 다르다.

참고로 위 value_iteration은 4.1절의 in-place 스타일이라, sweep 중에도 갱신된 값을 쓴다 — 그런데도 이 5칸 예에서는 sweep을 완전히 끝낸 뒤 갱신하는 synchronous 버전과 매 스텝의 값이 정확히 일치한다(앞 표의 \(V_k\) 행이 바로 두 버전 공통의 추적궤적). 이유는 이 GridWorld의 최적 전이가 오른쪽 방향으로만 이기 때문이다 — in-place sweep을 0→4 순서로 돌리면, 갱신 정보가 “아직 갱신 안 된” 상태에서 “이미 갱신된” 상태로만 흘러가므로 (sweep 순서가 정보 흐름과 반대 방향이므로) in-place는 sync와 동일하다. sweep 순서가 정보 흐름과 같은 방향이면(예: 상태 순서를 4→0으로 뒤집으면) in-place가 한 sweep 안에 정보를 더 멀리 전파해 더 빠르게 수렴할 수 있다 — 4.1절 “수학적으로 정확히는 어떤 반복인가“에서 본 바와 같이. 두 버전은 같은 고정점에 수렴한다는 보장은 변하지 않는다.

정책반복과 가치반복은 “같은 알고리즘의 두 극한”

4.2절 FAQ에서 예고했듯, 정책평가를 완전 수렴 없이 \(k\)sweep만 돌리고 바로 정책개선으로 넘어가는 변형(수정된 정책 반복, modified policy iteration)을 \(k\)에 따라 나열하면,

\(k\)이름바깥 반복총 sweep결과 \(V(0)\)
1가치 반복55-3.439
2수정된 정책반복48-3.439
4수정된 정책반복28-3.439
\(\infty\)정책 반복210-3.439

가치반복과 정책반복은 따로따로 배운 “다른 알고리즘“이 아니라, 같은 프레임워크의 연속 스펙트럼 양 끝단인 셈이다(위 5칸 GridWorld, 4.2절의 초기 정책 “무조건 오른쪽“에서 출발, V는 스윕마다 이어서 쓰는 warm start — 노트북 §3에서 재현할 수 있다). \(k\)를 키우면 바깥 반복은 줄고 각 반복이 무거워지며, 극단 \(k=1\)이 가치반복, \(k=\infty\)가 정책반복이다.

중요: “평가 횟수 \(k\)가 적다고 최종 답이 안 나온다.” 표에서 보듯 \(k=1\)부터 \(k=\infty\)까지 모두 정확히 같은 \(V^*\)에 도달한다 — 차이점은 오직 바깥 반복 횟수와 총 sweep 수(=총 계산량)뿐이다. \(k\)를 줄이면 개별 정책개선이 “아직 정확하지 않은” \(V\) 기준으로 이루어지지만, 정책은 한 번도 나빠지지 않으며(4.2절의 정책개선 단조 증가 성질) 유한한 정책 개수(\(2^5 = 32\)개) 안에서 결국 최적 정책에 착근한다. 그래서 실전에서는 “정확한 답“은 변하지 않으니 총 계산량만 줄이려고 \(k\)를 작게(2~10 정도) 잡는 것이 표준 트릭이다 — \(k\)가 너무 작으면 개선의 방향 감각이 떨어져 바깥 반복이 늘고, 너무 크면 4.2절의 “완전 평가“처럼 각 반복이 비싸지는 Trade-off가 \(k\)라는 하나의 수로 조절되는 구조다.

왜 이 반복이 수렴하는가: 바나흐 고정점 정리

“적어도 하나의 최적 정책이 항상 존재한다“는 사실은 자명하지 않다 — 어떤 상태에서는 정책 \(\pi\)가 낫고 다른 상태에서는 \(\pi’\)이 나을 수 있어서, “모든 정책 중 최댓값“이라는 개념 자체가 무너질 수도 있기 때문이다. 이 문제는 4.1·4.3절의 우변(벨만 기대방정식과 벨만 최적방정식 각각의 우변)을 하나의 연산자 \(T\)로 보면 풀린다 — \(T\)는 \(\gamma\)-축소 사상(contraction mapping)이라는 것이 증명돼 있다: 임의의 두 가치함수 \(V_1, V_2\)에 대해,

\[\|TV_1 - TV_2\|_\infty \le \gamma \|V_1 - V_2\|_\infty\]

즉 \(T\)를 한 번 적용할 때마다 두 함수 사이의 (최대) 차이가 최소 \(\gamma\)배로 줄어든다. 바나흐 고정점 정리(Banach fixed point theorem)는 이런 축소 사상이 항상 유일한 고정점을 가지고, 어디서 출발해 반복해도 그 고정점에 수렴한다는 것을 보장한다 — 그래서 벨만 최적방정식을 만족하는 \(V^*\)가 존재하고 유일하며, 가치반복(임의의 값에서 시작해 \(T\)를 반복 적용하는 것)이 실제로 그 값에 도달한다.

\(V^*\)를 알면, 각 상태에서 그 \(\max\)를 실제로 달성하는 행동을 그대로 고르는 결정론적 정책 \(\pi^*\)를 만들 수 있다. 이 정의가 항상 가능한 이유는 단순하다 — 각 상태에서 고를 수 있는 행동의 집합이 유한하기 때문에, 유한집합의 최댓값은 항상 어딘가에서 달성된다.

이 증명이 보장하는 건 “존재“이지 “계산 가능성“이나 “저장 가능성“이 아니라는 점도 중요하다 — 바둑처럼 상태 수가 초천문학적으로 많으면(약 \(10^{170}\)), \(\pi^*\)가 이론적으로 존재해도 모든 상태에 대해 표로 저장하는 것 자체가 불가능하다. Chapter 9(DQN)에서 배울, 표 대신 신경망으로 근사하는 방법이 필요해지는 이유가 바로 여기서 나온다. (이 거듭제곱법이 왜 수렴하는지는, 그래프 위에서 무작위 걷기의 정상분포를 구하는 Chapter 14.3의 PageRank 알고리즘과 정확히 같은 수학이다.)

모델 기반이라는 전제

이번 장의 모든 알고리즘은 전이확률 \(P(s’|s,a)\)를 정확히 알고 있다는 전제 위에 서 있다 — 체스라면 “이 수를 두면 상대는 어떻게 반응할 확률이 얼마인가“를 미리 다 알아야 한다는 뜻인데, 현실에서는 대부분 이걸 알 수 없다. Chapter 5·6은 이 모델을 몰라도 경험만으로 학습하는 방법(몬테카를로, 시간차 학습)을 다룬다.

동적계획법의 핵심 아이디어(“큰 문제 = 작은 부분 문제 + 재귀”)는 컴퓨터공학 전반에서 반복해서 등장하는 패턴이고, 강화학습은 그 패턴을 “미래의 불확실한 보상을 어떻게 지금 계산할 것인가“라는 문제에 적용한 것이다 — 그리고 그 반복이 항상 정답에 수렴한다는 것 자체가, 축소 사상이라는 하나의 수학적 성질로 보장된다.

2. (손유도, Tier B — 힌트 제공) 다음 3-state MDP를 놓고 각 상태의 가치 \(V(s)\)를 구한다: State 0은 항상 State 1로 이동(보상 -1), State 1은 항상 State 2로 이동(보상 -1), State 2는 종료 상태(\(V(2)=0\)). 할인율 \(\gamma = 0.9\).

벨만방정식 \(V(s) = R(s) + \gamma V(s’)\)을 State 2(터미널)부터 거꾸로 대입하여 \(V(1), V(0)\)을 직접 계산하라.

힌트: 터미널 상태부터 거꾸로 풀면(backward induction) 연립방정식을 한 번에 풀 필요 없이 대입만으로 답이 나온다. \(V(2) = 0\) → \(V(1) = -1 + 0.9 \times V(2) = ?\) → \(V(0) = -1 + 0.9 \times V(1) = ?\)

정확성 확인: 문제 1의 policy_evaluation으로 같은 MDP를 실행했을 때 나오는 값과 손계산 값이 일치하는지 비교하라.

3. (손유도, Tier C — 폴백 준비 대상) \(T\)가 \(\gamma\)-축소 사상이라는 성질 \(\|TV_1 - TV_2\|_\infty \le \gamma \|V_1 - V_2\|_\infty\)을 받아들이고, 이로부터 “임의의 초기값 \(V_0\)에서 시작해 \(T\)를 반복 적용하면 \(V^*\)로 수렴한다“는 결론이 왜 따라 나오는지 논증하라.

빈칸채움형 폴백 버전 (자유 논증이 어려운 경우):

가정: T는 gamma-축소 사상이고, V*는 T의 고정점(TV* = V*)이다.

Step 1: ||V_1 - V*|| = ||TV_0 - TV*|| <= gamma * ||______________||
Step 2: 같은 방식으로 ||V_2 - V*|| = ||TV_1 - TV*|| <= gamma * ||______________||
                                    <= gamma^2 * ||______________||
Step 3: n번 반복하면 ||V_n - V*|| <= gamma^n * ||______________||

결론: gamma < 1이므로 n이 커질수록 gamma^n은 ______________ (0에 가까워진다/커진다)
      따라서 V_n은 ______________ (V*로 수렴한다/발산한다)

정확성 확인: 이 결과가 “정책평가·가치반복이 초기값 \(V_0\)를 아무렇게나(예: 전부 0으로) 잡아도 항상 같은 답에 도달한다“는 사실을 왜 보장하는지 한 문장으로 설명하라.
