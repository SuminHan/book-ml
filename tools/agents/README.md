# 슬라이드 개편 오케스트레이션 스펙

2,237개 프레임(글자만 65%, 중앙값 412자)을 발표용으로 얇게 만드는 작업을
모델 등급별로 나눠 돌리기 위한 규칙. **이 문서는 오케스트레이터(Opus)가 지킬 규칙이고,
서브에이전트용 프롬프트는 옆 파일에 따로 있다.**

## 등급 배분 원칙

작업을 모델에 배정하는 기준은 난이도가 아니라 **"틀렸을 때 기계가 잡아낼 수 있는가"**다.

| 등급 | 누가 | 맡는 일 | 배정 근거 |
|---|---|---|---|
| T0 | Opus (오케스트레이터) | 루브릭 확정, few-shot 직접 작성, 샘플 감사, 실패 케이스 처리, 커밋 | 되돌리기 어려운 판단 |
| T1 | Qwen3-8B (연구실 서버) | `\item` 단위 KEEP/NOTE 분류 — **수천 건** | 출력이 스키마로 강제되고 검증이 결정적. 무료·무제한·오프라인 |
| T2 | Sonnet 5 서브에이전트 | 웹 이미지 소싱, 라이선스 판정 | 웹 접근 + 판단 필요 → Qwen 불가 |
| T3 | Haiku 4.5 서브에이전트 | 빌드 로그 파싱, Overfull 집계, 링크 생존 확인 | 기계적 반복, 판단 없음 |

Claude 등급은 `Agent` 툴의 `model` 파라미터로 지정한다 (`"sonnet"` / `"haiku"`).
Qwen은 별도 HTTP 호출(아래).

## T1이 LaTeX을 쓰지 않게 하는 것이 이 설계의 핵심

8B 모델에게 LaTeX 재작성을 시키면 `\kb{}` 중괄호를 깨고, 한글을 흘리고,
없던 매크로를 지어낸다. 그래서 **생성이 아니라 분류만 시킨다.**

1. 파이썬이 프레임을 `\item` 단위로 쪼개고 **번호를 붙여** Qwen에 넘긴다.
2. Qwen은 각 번호에 `KEEP` / `NOTE` / `DROP` 라벨만 붙인다. 원문은 손대지 않는다.
3. 파이썬이 라벨대로 LaTeX을 **결정적으로** 재조립한다 (`NOTE` → `\note{}` 로 이동).

결과: 내용 보존이 *증명 가능*해진다 — 원본 item 집합과 (슬라이드 ∪ 노트) 집합이
정확히 일치해야 하고, 새로 생성된 문장은 원리적으로 0개다.

## 결정적 검증기 (LLM 없음, 통과 못하면 사람에게)

`tools/agents/verify.py`가 프레임마다 전부 통과시켜야 커밋 후보:

- [ ] 원본 item이 **정확히 한 번씩** 슬라이드나 노트에 등장 (`DROP`은 명시 승인분만)
- [ ] 매크로 화이트리스트 `\kb \kq \ksacredit` + 표준 beamer 밖의 매크로가 새로 등장하지 않음
- [ ] 중괄호·`$` 짝 맞음
- [ ] `tectonic -X compile` 종료코드 0
- [ ] 해당 프레임에 **새 Overfull vbox 없음** (기존 목록 대비 diff)
- [ ] 슬라이드 본문 ≤ **180자** (목표치. 412자 → 180자)

## 킬 크라이테리아 — 먼저 20개로 재고 결정한다

Phase 0에서 내가 직접 20개 프레임을 라벨링해 정답셋을 만든다.
Qwen과 item 단위 **일치율 < 80%** 면 T1은 폐기하고 내가 직접 한다.
일치율은 측정 후 이 줄에 기록한다: `측정값: (미측정)`

## Qwen 서빙 설정 (연구실 서버)

```bash
vllm serve Qwen/Qwen3-8B \
  --port 8000 --max-model-len 8192 \
  --guided-decoding-backend xgrammar
```

- **OpenAI 호환 API + `guided_json`** 을 반드시 쓴다. 스키마 강제 디코딩이면
  파싱 실패가 구조적으로 0이 된다. Ollama는 이게 약해서 권하지 않는다.
- `chat_template_kwargs: {"enable_thinking": false}` — 이 작업은 규칙 적용이라
  thinking이 처리량만 깎는다.
- `temperature: 0` — 분류 작업.
- 배치: 프레임 1개 = 요청 1개, 동시 16.
- 접속: 랩 서버가 외부에 안 열려 있으면 `ssh -N -L 8000:localhost:8000 <lab>`.

> **모델 선택 참고**: GPU가 24GB 이상이면 **Qwen3-30B-A3B**(MoE, 활성 3B)가
> 8B와 비슷한 속도에 품질은 크게 낫다. 이 작업의 품질을 좌우하는 가장 큰 변수는
> 프롬프트가 아니라 모델 크기다. 8B는 "되면 이득" 쪽으로 보는 게 맞다.

## 이미지 작업은 별도 파이프라인 — 찾기 전에 "만들 수 있나"부터

이 저장소는 smhanlab.com/book-ml 로 **공개 배포**된다. 웹 이미지를 긁어 넣는 건
실제 저작권 리스크이고, 이미 `kor/src/images/ref_gmm_vs_kmeans.png`(개인 블로그 출처)가
그 상태다. 그래서 이미지 요청은 아래 순서로만 처리한다:

1. **생성 가능한가?** — 개념 도식, 분포, 결정경계, 학습곡선, 알고리즘 비교는
   전부 matplotlib/TikZ로 만들 수 있다. 저장소에 이미 파이프라인이 있다
   (`kor/src/images/*.svg` → `build_figs.sh`). 라이선스 깨끗, 한글 라벨,
   스타일 일관, 수정 가능. **이게 기본값이다.**
2. **진짜 웹에서 와야 하는가?** — 실제 데이터셋 샘플 이미지, 역사적 사진,
   특정 논문 figure, 실제 제품 화면. 이때만 T2 이미지 스카우트를 부른다.
3. **수집 화이트리스트** — 자동 수집은 라이선스가 기계판독 가능한 곳만:
   Wikimedia Commons(CC/PD), scikit-learn·matplotlib·PyTorch 공식 문서(BSD/MIT),
   명시적 CC-BY arXiv figure. **그 외(개인 블로그, Medium, 이미지 검색 썸네일)는
   자동 채택 금지** — 후보로만 올리고 사람이 판단한다.
4. 채택된 이미지는 `kor/src/images/CREDITS.md`에 출처·라이선스·URL·수집일을
   반드시 기록한다. 이게 없으면 커밋하지 않는다.

한국 저작권법 제25조(학교교육 목적 이용)는 **수업 현장** 이용을 다루지,
공개 웹사이트 배포를 보장하지 않는다. 발표용 PDF와 웹 공개용 PDF를 나눠야 한다면
그 경계에서 나눈다.

## 작업 큐 흐름

```
프레임 선별(나)  →  T1 Qwen 분류  →  결정적 재조립(py)  →  검증기(py)
                                                             ├─ 통과 → 내가 10% 표본 감사 → 커밋
                                                             └─ 실패 → 내가 직접 처리
        └→ Qwen이 needs_figure=true 로 표시한 것 → 내가 "생성 vs 검색" 분류
                                                    ├─ 생성 → 노트북/TikZ (나 또는 T3)
                                                    └─ 검색 → T2 이미지 스카우트 → 내가 라이선스 최종 확인
```
