### ML1 총정리

이번 학기는 선형/로지스틱회귀의 경사하강법에서 시작해, 생성적 분류(나이브
베이즈/GDA[^gda]), 거리·마진 기반 모델(kNN, SVM), 트리 앙상블(GBDT), 신경망(역전파,
CNN), 시퀀스·어텐션·LLM, 비지도학습(PCA, 임베딩), 잠재변수 생성모델(EM/GMM,
VAE[^vae], GAN[^gan], Diffusion[^ddpm])까지 왔다.

| 장 | 배운 것 | 핵심 질문 |
|---|---|---|
| Ch02 | 선형·로지스틱회귀 | 연속값과 확률을 어떻게 예측하는가 |
| Ch03 | 나이브베이즈/GDA | 데이터가 어떻게 생성됐는지부터 거꾸로 분류할 수 있는가 |
| Ch04 | kNN/k-means | "가깝다"만으로 예측·군집화할 수 있는가, 그 한계는 무엇인가 |

| Ch06 | 정규화/모델선택 | 과적합을 손실함수로 어떻게 통제하는가 |
| Ch07 | 트리/랜덤포레스트/GBDT/SHAP[^shap] | 데이터를 잘 나누는 질문을 어떻게 고르고, 그 예측을 어떻게 설명하는가 |
| Ch09 | 신경망/역전파/학습기법 | 층을 어떻게 학습시키고, 깊은 신경망은 왜 학습이 어려운가 |

| Ch12 | 어텐션과 트랜스포머[^transformer] | 순차 처리 없이 모든 단어의 관계를 어떻게 한 번에 계산하는가 |
| Ch13 | LLM: 사전학습/프롬프팅/정렬 | 다음 토큰 예측이 어떻게 폭넓은 능력이 되고, 그걸 사람 뜻에 맞게 어떻게 다듬는가 |
| Ch14 | PCA/임베딩/PageRank | 정답 없이 데이터·그래프의 구조를 어떻게 찾는가 |
| Ch15 | EM/GMM/VAE/GAN/Diffusion | 관측되지 않은 잠재변수로부터 어떻게 새 데이터를 만들어내는가 |

공통된 흐름을 돌아보면: **모델을 정의하고 → 틀린 정도를 손실함수로
수치화하고 → 그 손실을 줄이는 방향으로 파라미터를 조정한다**는 구조가
거의 모든 장에서 반복됐다.

이 반복은 "교재를 통일감 있게 보이게 하려는" 우연이 아니다 — 이것이
바로, 이 학기의 첫 질문이 **"무엇을 데이터로 갖고 있고, 무엇을 맞히고
싶은가"**(16.1 발표의 마지막 필수 질문)인 *이유*다. 모델은 **선택**이지만,
이 4단계 구조는 **의무**다. GDA든 100층 트랜스포머든 "모델 정의 →
틀린 정도 수치화 → 파라미터 조정"을 거치지 않는 모델은 없다. 그래서
새 문제를 만났을 때 시작할 생각은 "어느 장의 도구를 쓸 것인가"가
아니라 **"이 문제는 4단계 중 어디에 걸리는가**"여야 한다 — 데이터가
표인가, 이미지인가, 토큰인가? 정답(\\(y\\))이 있는가? 틀린 정도를
무엇으로 재는가? 아래 표는 Block A와 Block B를 이 4단계로 나란히
세운 것이다.

| 단계 | Block A (Ch02~07) | Block B (Ch09~15) |
|---|---|---|
| ① 모델을 정의 | 선형 \\(w^Tx+b\\), 결정 트리 (Ch02, 07) | 겹친 층의 네트워크, GAN은 두 개의 네트워크 (Ch09, 15) |
| ② 손실 | MSE, 교차엔트로피, 힌지 (Ch02, 05) | ELBO, min-max (Ch15.2, 15.3) |
| ③ θ 조정 | 경사하강·정규방정식 (Ch02), EM (Ch15.1) | 역전파 (Ch09), 적대적 학습 (Ch15.3) |
| ④ 과적합 통제 | \\(\lambda\\) 정규화, 교차검증 (Ch06) | dropout[^dropout], early stopping (Ch09.3) |

특별히 짚을 행은 GAN(Ch15.3)이다 — ②③이 "손실 하나, 방향 하나"가
아니라 생성자와 판별자가 **동시에 최소화/최대화하는 게임**이다. ③을
"경사를 내리막"이 아니라 "두 플레이어의 균형(내쉬 균형, D=0.5)"으로
바꿔둔 것이, ML2에서 *보상*이 *손실*보다 더 큰 도약인 이유의 선구
(§"ML2의 로드맵")다.

### 프로젝트 채점: 점수가 나왔을 때 실제로 보는 것

기말 프로젝트 점수는 세 산출물 — **발표(16.1, 5~7분)**, **보고서(5~8페이지)**,
**peer 리뷰(16.2, 2건)** — 의 합산이다. 비중은 다음과 같다.

| 구성 | 비중 | 보는 것 |
|---|---|---|
| 발표 | 50% | 16.1 채점 기준 5항목 — 특히 "결과의 정직성과 반성"(마지막 1분) |
| 보고서 | 30% | 발표의 주장이 **코드로 재현 가능한가** — 8.1 보고서 구조 6절 |
| Peer 리뷰 (2건) | 20% | *네가* 쓴 질문의 품질 — 8.2의 3단 기준(감상평/일반 지적/반박 가능한 질문) |

"남의 프로젝트 리뷰"가 왜 *자기* 점수에 들어가는가. 8.2에서 이미 답을
봤다 — 좋은 리뷰는 발표팀의 결과를 단단하게 만들고, 그 행위는 Amgen이[^amgen]
스스로 논문 53편을 재현해 본 것과 같은 과학적 행위다. 그러니 "리뷰를
잘 쓴 사람"은 이 학기의 절차를 가장 깊게 이해한 사람이라는 뜻이고,
채점이 그것을 반영하는 것이다.

**결실 사례: 숫자를 바꾼 리뷰.** 이 블록 1번 순서에서 발표하는 사례의
이상적인 형태는 "리뷰가 단순한 비판이 아니라 **수정을** 만든" 경우다.
예를 들어, 어떤 팀의 발표: "흉부 X-광 CNN, test 정확도 94%. 증강
6가지 변형을 시도해 가장 좋은 것을 골랐다." 리뷰어의 3점 질문: "6개
변형 중 **test로** 고른 것은 Ch06.3의 선택 편향이다 — 후보 6개면
\\(\\mathbb{E}[\\max] \\approx 0.025\\) 정도의 부풀림이 있다. val 정확도는
몇 %이고 test와의 격차는?" 팀이 다시 확인해 보면, 이번엔 *다른*
원인이 드러난다 — 같은 환자의 여러 X-광이 train과 test에 동시에
들어 있었다(그룹 누수, 6.3). 환자 단위로 다시 나누자 test 정확도가
94% → 88%로 떨어졌다. "정확도 94%"라는 발표는 리뷰 한 통으로
"정확도 88%, 그 이유까지"라는 **더 좋은 발표**로 바뀌었다 — 이것이
peer-review가 정상 작동한 모습이다.

반대의 경고도 함께 둔다. 리뷰 후 "다시 확인"을 할 때, 사람은 원래
결론을 더 쉽게 다시 찾게 된다(자기에게 유리한 편향). 그래서 보고서에
**리뷰 답변을 별책으로** 첨부하는 것이 좋은 관행이다 — "무엇을 다시
확인했는지" 자체가 기록이 되므로, 확인이 진짜로 일어났는지(그리고
숫자가 실제로 바뀌었는지)가 추적 가능해진다.

### Peer-Review 결실: 3단 기준을 마지막에 한 번

리뷰 2건의 체크리스트는 8.2와 동일하고(문제 정의, 방법론 적절성,
수식적 정당화, 결과의 정직성) 16.2의 추가 항목("왜 고전 ML이 아니라
딥러닝인가")이 더해진다. 3단 기준(1점 감상평 / 2점 일반 지적 /
3점 반박 가능한 질문)도 그대로 적용된다 — 바뀌는 것은 **재료**다.
딥러닝 프로젝트에서 가장 자주 나타나는 두 리뷰 패턴을 3단으로
나란히 놓고 본다.

**예시 1 — 선택 편향 질문.**

> **발표 요약**: "흉부 X-광에 CNN을 학습해 폐렴을 분류했다. 데이터
> 증강 6가지 변형을 시도해 가장 좋은 것을 골랐고, test 정확도 94%를
> 달성했다."

| 단계 | 리뷰 |
|---|---|
| 1점 (감상평) | "증강 학습을 활용하셨군요. 결과가 인상적입니다." |
| 2점 (일반 지적) | "증강 6가지를 어떻게 고르셨는지 기준이 부족해 보입니다." |
| 3점 (반박 가능한 질문) | "6개 변형 중 **test 성능으로** 고른 것은 Ch06.3의 선택 편향입니다(개념) — 후보 6개이면 정확도가 \\(\\mathbb{E}[\\max] \\approx 0.025\\) 부풀려져 있을 수 있습니다(왜). val 정확도와 test 정확도의 격차를 보여주세요 — 격차가 0.025 미만이면 그 격차는 부풀림 크기보다 작으므로 'test로 고르지 않았다'는 근거가 됩니다(구체적 산출물)." |

**예시 2 — "왜 딥러닝인가" 질문 (16.2 추가 항목).**

> **발표 요약**: "고객 이탈 예측(정형 테이블 데이터)에 Transformer를
> 적용해 test 정확도 81%를 얻었다. 최신 아키텍처라 기대가 컸다."

| 단계 | 리뷰 |
|---|---|
| 1점 (감상평) | "최신 모델을 적용하셨네요. 81%는 좋은 결과입니다." |
| 2점 (일반 지적) | "정형 데이터에 Transformer를 쓴 근거가 약해 보입니다." |
| 3점 (반박 가능한 질문) | "정형 데이터에서 GBDT[^gbdt] (Ch07.3)는 신경망과 동일하거나 높은 성능이 흔합니다 — 같은 데이터의 GBDT val F1은 얼마인가요(관찰 요구)? Transformer가 여기서 주는 **구체적 구조적 장점**(데이터 규모, 상호작용 패턴)이 무엇이고, 그 장점이 숫자 어디에 보입니까(개념)? 새 계산 없이 답할 수 없다면 '딥러닝이 필요했다'는 결론이 성립하지 않습니다." |

두 예시의 3점 질문은 같은 형태를 가진다 — **관찰(발표에서 본 것) +
개념(장 번호) + 왜 문제인지 + 구체적 산출물 요구**. 그 네 칸이 모두
채워져야 "발표팀이 '좋은 지적입니다'로 넘길 수 없는" 질문이 된다
(8.2 FAQ). 이 학기 동안 발표자는 2회(8.1, 16.1), 리뷰어는 2회
(8.2, 16.2)였다 — "반증 가능성(falsifiability)"이라는 8.2의 말이
이제 낯선 단어가 아니라면, 이 절차는 끝난 것이다.

### ML1 개념지도

![ML1(Ch02~15) 개념지도 — 4개 박스: ① 데이터와 문제 정의(행의 단위/정답의 유무/데이터의 형태/베이스레이트) → ② 모델(선형·생성적·거리·트리·신경망·CNN·RNN·어텐션·LLM·비지도·잠재변수 생성, 10가지 도구) → ③ 학습: 거의 모든 장에서 반복되는 4단계 구조(모델 정의→손실로 수치화→θ 조정→과적합 통제) → ④ 평가(3분할·전처리 train fit / 하이퍼파라미터는 val에서만 / test는 딱 한 번). 붉은 점선은 ④에서 ①로 돌아감(과적합·누수면 다시), 금색 점선은 ③에서 ML2로 나감(정답 y가 보상 r로, 데이터가 에이전트의 경험으로 바뀜)](../../images/ch16_3_concept_map.svg)

그림은 이 학기 절차의 4개 박스 — 데이터 → 모델 → 학습 → 평가 — 와
색상 두 줄이다. **붉은 점선**("과적합·누수면 돌아가서 다시")는 Ch06.3
의 원칙 — 프로젝트에서 되돌아갈 수 없는 것은 test 한 번의 측정뿐이다 —
이고, **금색 점선**은 ML2로 나가는 다리(아래 절)다.

이 지도의 쓰기는 단순하다: **Ch02~15의 모델을 하나 골라 ①②③④에
놓아본다.** GMM(Ch15)은 ③에서 "EM이 관측 데이터의 우도를 최대화하는
방향으로 θ를 조정", VAE(Ch15.2)는 ②에서 "ELBO가 우도의 하한"
(Gaussian assumption 하의 exact MLE는 어려우므로), GAN(Ch15.3)은
③에서 "min-max — 게임". 세 개를 전부 놓을 수 있으면, 이 학기는
정말 끝난 것이다.

### 확인 문제: 기말고사 대비 장을 넘나드는 복습 문제 4개

**1.** Chapter 3의 GDA와 Chapter 15의 GMM은 둘 다 "정규분포를 가정한
생성적 모델"이라는 공통점이 있다. 가장 핵심적인 차이는 무엇인가?
> 답: GDA는 클래스 라벨 \\(y\\)가 **관측되는**(지도학습) 상황에서
> 각 클래스의 분포를 추정하지만, GMM은 클러스터 소속(\\(z\\))이
> **관측되지 않는**(비지도학습) 상황에서 EM으로 그 잠재변수까지
> 함께 추정해야 한다.

**2.** Chapter 7의 트리 기반 모델과 Chapter 10의 CNN은 둘 다 "국소적인
정보"를 활용하는 귀납적 편향을 갖는다. 각각 어떤 방식으로 이 편향을
구현하는가?
> 답: 트리는 한 번에 특징 하나씩만 보고 분기해서 저차원적인 규칙을
> 조합하고, CNN은 작은 필터가 이미지의 국소 영역만 보고 그 필터를
> 전체 이미지에 재사용(파라미터 공유)한다 — 형태는 다르지만 "전체를
> 한 번에 보지 않고 지역적으로 나눠서 본다"는 방향은 같다.

**3.** Chapter 9의 그래디언트 소실 문제가 Chapter 11(RNN)과 Chapter
10(ResNet)[^resnet]에서 각각 어떤 해법으로 재등장하는가?
> 답: ResNet은 스킵 연결(\\(y=F(x)+x\\))로 그래디언트가 "+1" 항을
> 통해 그대로 전달될 경로를 만들고, LSTM/GRU(Chapter 11.3)[^gru]도 게이트를
> 통해 정보가 곱셈 대신 덧셈으로 흐르는 경로를 만든다 — 서로 다른
> 구조(이미지 vs 시퀀스)에서 같은 해법(곱셈 사슬에 덧셈 지름길을
> 낸다)이 독립적으로 재발견된 것이다.

**4.** Chapter 12의 어텐션과 Chapter 15의 VAE는 둘 다 "가중합"이라는
연산을 핵심으로 쓴다. 각각 무엇의 가중합을 계산하는가?
> 답: 어텐션은 softmax로 정규화된 관련도(가중치)로 각 단어의 Value
> 벡터들의 가중합을 계산해 "관련 있는 정보를 섞은" 새 벡터를 만든다.
> VAE의 ELBO는 (가중합은 아니지만) "복원 항"과 "KL 정규화 항"이라는
> 서로 다른 두 목표의 균형을 하나의 손실로 합친다는 점에서, "여러
> 신호를 하나로 종합한다"는 더 넓은 패턴을 공유한다.

### 추가 복습 문제: 프로젝트 절차 자체가 개념인 이유

위 4문항은 "개념끼리의 연결"을 묻고, 아래 3문항은 "프로젝트 절차
자체가 개념"임을 묻는다 — 16.1의 발표와 16.2의 리뷰에서 바로 쓰는
판단력이다.

**5.** 어떤 팀의 보고서에 "하이퍼파라미터 조합 8개를 시도해 가장 좋은
것을 보고했다"고 적혀 있고, 발표 숫자는 "test F1 0.97"이다. Ch06.3의
선택 편향 계산으로 부풀림 크기를 추정하고, 이 팀에 던질 반박 가능한
질문 하나를 쓰자.
> 답: 후보 8개는 8.1절 표에서 5개(\\(\\approx 0.023\\))와 50개
> (\\(\\approx 0.045\\)) 사이의 \\(\\approx 0.03\\) 부풀림 — "0.97"이
> 실제로는 0.94 부근일 수 있다. 질문 예: "8개 조합 중 val F1로 고른
> 것과 test F1로 고른 것의 차이는 얼마인가요? val F1과 test F1의
> 격차가 0.02 미만이면 그 격차는 선택 편향 크기보다 작아 — test로
> 고르지 않았다는 근거가 없습니다."

**6.** 실습 노트북 §8에서 "누수된 test"의 정확도는 1.000, 실제 test
정확도는 0.947(차이 +0.053)이었다. 모델과 하이퍼파라미터를 **하나도
바꾸지 않고** 이런 차이가 가능한가, 그리고 그런 숫자의 팀에게 리뷰어는
무엇을 물어보는가?
> 답: 가능하다 — **분할 방식 하나**가 바뀌면 된다. train에 이미 있는
> 같은 단위(환자/행)를 test에 넣는 그룹 누수(Ch06.3). 리뷰 질문은
> 판단이 아니라 기계적 점검이다: "train과 test에 같은 환자가
> 동시에 들어갔나요? `GroupKFold`로 재분할하면 test F1이 어떻게
> 변하나요?" — 분할 코드 한 줄을 보면 즉시 판정된다.

**7.** 16.1 발표의 필수 질문 "왜 고전 ML이 아니라 딥러닝인가"에
"딥러닝이 최신이라서"라고 답하는 팀을 8.2의 3단 기준으로 평가하고,
그 답을 3점 질문으로 바꿀 수 있는 질문을 쓰자.
> 답: "최신이라서"는 관찰도 개념도 없는 추상적 평가어가므로
> 1~2점에 머문다. 3점 질문 예: "같은 데이터에 GBDT(Ch07.3)를 돌리면
> val F1은 얼마인가요? 그 네트워크가 주는 구체적 구조적 장점이
> 숫자 어디에 보입니까?" — 새 계산 없이 답할 수 없으므로
> 반박 가능하다.

### 실습: 검증 절차를 한 흐름으로 끝까지

이 절의 실습 노트북(페이지 상단의 Colab 배지)은 기말 프로젝트의
**절차 전체**를 breast_cancer[^breast_cancer] (569건 × 30 특성)로 한 흐름에 실행한다 —
새 개념이 아니라, 이 절의 채점·리뷰·총정리가 "감"이 아니라
**숫자**에 뿌리박는지 확인하는 실험이다.

1. **문제 정의** — 행=환자, 라벨=악성(1)/양성(0), 주 지표 F1 (양성
   비율 62.7%라 정확도보다 F1).
2. **3분할** — train 341 / val 114 / test 114(stratify, seed 0).
3. **5개 모델 후보** (Ch02/04/07.1/07.2/07.3)를 **val F1로만**
   순위 — logreg 0.993 > kNN 0.979 > RF 0.957 > GBDT 0.950 >
   tree 0.944. (기말 프로젝트는 Ch09~15 딥러닝 기법을 요구하지만
   절차는 모델 종류와 무관하다 — 같은 절차를 Block A 모델로 시연.)
4. **베이스라인** — 다수 클래스(악성) 모델 val F1 0.768. 1위 모델과
   격차 **+0.225** — 이 격차가 "모델을 만들었다"는 증거다.
5. **test 딱 한 번** — val 1위(logreg)로 test accuracy 0.974,
   F1 0.979.
6. **선택 편향** — 50개 후보 중 test 최고를 고르면
   \\(\\mathbb{E}[\\max] \\approx 0.045\\) 부풀림(§"추가 복습 문제"
   5번의 숫자).
7. **val 순위 vs test 순위** — 이 데이터에서는 두 순위가 일치한다.
   그러나 그것은 **우연이지 보장이 아니다**(§7, 아래 그림).
8. **누수 시연** — (a) 스케일러를 전체 데이터로 fit해도 잘 섞인
   깨끗한 데이터에서는 val F1이 **동일**(0.979 = 0.979) — "보이지
   않는 누수". (b) train의 같은 행 50건을 "test"로 넣으면 정확도
   0.947 → **1.000**(+0.053) — 모델·하이퍼파라미터 불변, **분할
   방식만**.

![val F1 vs test F1 — 5개 모델의 val F1(파랑, 순위 결정에 사용)과 test F1(남, 딱 한 번 측정)을 나란히; 붉은 점선은 다수 클래스 베이스라인(0.768). 이 데이터에서 val/test 격차는 작지만, 그 격차가 "작다"는 것은 보장이 아니라 이 데이터의 운 — §6의 E[max]가 그 격차가 뒤집힐 수 있는 폭을 정한다](../../images/ch16_3_val_test_f1.svg)

§8의 (a)가 이 절에서 가장 오래 남을 숫자다. 누수의 위험성은 "해로움"이
**증명될 수 없어서**가 아니라 **보이지 않아서**다 — 깨끗한 데이터에서
정규화 통계를 전체로 fit하면 *어떤 신호도 없다*(val F1 0.979 = 0.979).
그리고 (b)처럼 *보일 때*도(+0.053), 그것 역시 "알고 보러" 갔을 때만
보인다. 그래서 6번 추가 복습 문제의 리뷰 질문이 *판단*이 아니라
*기계적 점검*("같은 환자가 train과 test에 동시에 들어갔나요?")인
것이다 — 깨끗한 데이터에서는 누수가 숫자에 드러나지 않으므로,
**절차(분할 코드**)가 유일한 방어선이다.

### ML2로 가기 전에

ML1은 "정답이 있는 데이터로부터 배운다"는 지도학습·비지도학습의 세계였다.
ML2는 완전히 다른 질문에서 출발한다 — 정답 대신 **보상**만 주어지고,
데이터가 미리 있는 게 아니라 에이전트가 스스로 행동하며 만들어지는
**강화학습**의 세계다. 그리고 그 무대는 텍스트나 이미지가 아니라, 물리
법칙이 지배하는 **로봇 시뮬레이션 환경**이다.[^suttonbarto]

ML1을 듣지 않고 ML2를 바로 듣기 시작해도 무방하다 — ML2 1주차가 이번
학기에서 필요한 신경망 기초를 압축해서 다시 짚어준다. 다만 Chapter
9(역전파)와 Chapter 6(정규화, 특히 교차검증)의 감각이 남아있다면 ML2를
훨씬 수월하게 따라갈 수 있을 것이다.

### ML2의 로드맵: 같은 구조, 다른 질문

"강화학습"이라는 말 자체는 1984년 Richard Sutton의 박사논문
(*Temporal Credit Assignment in Reinforcement Learning*)에서 처음
쓰인 것이다 — 그 학문적 조상은 B.F. Skinner의 조작적 조건화(행동주의,
1950년대)다. "보상만 보고, 틀렸다는 신호 없이" 배우는 문제를 학문화한
것이 바로 Sutton의 질문이었으니, ML2가 "ML1의 반대"가 아니라
**ML1의 질문에서 정답 \\(y\\)를 빼면 남는 문제**라는 점은 그 명칭의
연원에서도 읽힌다.

ML2 16개 장의 흐름과, 그것이 ML1의 어떤 장과 대응하는지:

| ML2 장 | 내용 | ML1에서의 대응 |
|---|---|---|
| Ch01 | 코스 소개, 신경망 미니 리뷰, Gymnasium[^gymnasium] 세팅 | Ch09(역전파)의 감각 확인 |
| Ch02 | 멀티암 밴딧 | "보상만"의 가장 간단한 문제 — 탐색/활용 트레이드오프 |
| Ch03 | MDP 정식화 | "데이터가 어떻게 만들어지는가"(Ch03) — 다만 데이터는 **에이전트가 스스로** 만든다 |
| Ch04~07 | 동적계획법, 몬테카를로, TD, 적격흔적 | Ch15(EM)의 "추정" — 정답 없이 값 함수를 반복적으로 추정 |
| Ch08 | Block A 캡스톤 | 이 장과 동일한 구조(발표+리뷰+총정리) |
| Ch09~11 | 함수근사, DQN[^dqn], 정책기반, PPO[^ppo] | Ch09(역전파) + Ch06(과적합 통제)를 제어 문제에 |
| Ch12 | 모방학습, 인간 피드백(RLHF[^rlhf]) | Ch03의 생성적 모델, Ch13의 정렬을 RL로 |
| Ch13~15 | 로봇 시뮬레이션, MuJoCo[^mujoco]/Isaac[^isaacgym], 모델기반 RL | Ch10~11의 구조를 물리 무대 위로 |
| Ch16 | Block B 캡스톤과 학기 총정리 | 이 장과 동일한 구조 |

ML1과 ML2를 나란히 놓으면, 바뀌는 것이 무엇인지 한눈에 보인다:

| ML1 (정답 \\(y\\)가 있음) | ML2 (보상 \\(r\\)만) |
|---|---|
| 데이터셋(미리 주어져 있음) | 경험(에이전트의 **자기** 궤적 — 배우는 동안 데이터가 만들어진다) |
| 라벨 \\(y\\) (모든 행에) | 보상 \\(r\\) (보상만, 그것도 **늦게**와서) |
| 손실(틀린 정도) | 리턴(누적 보상) |
| 일반화 = test set 성능 | 일반화 = *다음* 환경(실제 로봇)에서 잘하는가 |
| 과적합 = train만 잘 맞음 (Ch06) | 과적합 = **시뮬레이터**에만 잘 맞음 (Ch14의 시뮬-실재 격차) |
| train/val/test 분리 (Ch06.3) | 탐색/활용 트레이드오프 (Ch02) — "데이터를 만들 권리"가 트레이드오프의 대상 |

그리고 개념지도의 4단계(① 모델 정의 → ② 손실 → ③ θ 조정 → ④ 통제)는
ML2에서도 그대로 살아 있다 — 바뀌는 것은 ①의 "모델"(정책
\\(\\pi(a|s)\\))과 ④의 "데이터"(에이전트의 경험)뿐이다. **같은
구조, 다른 질문** — 이것이 이번 학기가 ML2에 남기는 정확한 선물이다.[^cs234][^silvercourse]

### 자주 묻는 질문

**Q. 기말고사 대비 — 어디서부터 공부해야 하나요?**
위 "확인 문제 4개"와 "추가 복습 문제 3개"를 그 순서로. 4문항은
"개념끼리의 연결"을, 3문항은 "절차"를 묻는다. 추가 복습 문제
6번(누수 질문)을 노트북을 안 봐도 답할 수 있으면 준비 끝이다.

**Q. 복습 문제가 Ch02부터 Ch15까지 다 섞여 있는데, 기말은 Block B(Ch09~15)만 묻는 거 아닌가요?**
복습 문제가 의도적으로 두 블록을 넘나든다 — Block B의 개념은 Block A의
개념 위에 쌓여 있고(예: 문제 3의 그래디언트 소실은 Ch09 → Ch10 → Ch11로
이어진다), "연결을 아는가"가 "개별 장을 외우는 것"보다 훨씬 더
시험에서(그리고 ML2에서) 쓰이기 때문이다.

**Q. ML2를 계속 듣는데, ML1의 수식 유도를 전부 외워야 하나요?**
아니오 — 4단계 구조의 **감각**이 자동인 것이 목표다. 유도(GDA↔로지스틱
동치성, ELBO의 유도)는 필요한 때에 장에서 찾아보는 것(= API 문서
읽는 것)이 정상이고, "이 데이터의 손실은 뭐로 나타내지?"가 자동
반사처럼 돼야 한다.

**Q. ML2의 프로젝트(Ch16)는 이번 것과 무엇이 다른가요?**
뼈대(발표+리뷰+채점 기준)는 동일하다. 달라지는 것은 "결과의 정직성"
항목의 초점 — 강화학습에서는 "학습이 안 된 부분"이 실패가 아니라
**데이터**다(8.1, 16.1에서 예고한 대로) — "왜 안 됐는지"의 원인을
Ch09~15(그리고 ML2 Ch01~15)의 개념으로 진단하는 보고서가 좋은
보고서가 된다.

**한 학기 동안 반복해서 확인한 원칙 하나로 이 학기를 닫는다: 어떤 모델을
쓸지보다 먼저 물어야 할 질문은 항상 같다 — 이 문제는 무엇을 데이터로
