# Chapter 11. 팀 프로젝트: 구현 (Team Project: Implementation)

지금까지 10개 장 동안 배운 모든 것 — 손실함수를 정의하고, 그래디언트를
유도하고, 모델을 구현하고, 그 정확성을 논증하는 것 — 은 각각 독립된
장의 문제로 다뤄졌다. 마지막 두 장은 이 조각들을 하나의 완성된
프로젝트로 직접 조립해보는 시간이다.

## 11.1 왜 팀 프로젝트인가

실제 머신러닝 문제는 "이 장은 로지스틱회귀, 저 장은 CNN" 식으로
깔끔하게 나뉘어 있지 않다. 데이터를 정제하고, 어떤 모델이 적합한지
판단하고, 학습이 잘 안 될 때 원인을 진단하고(과적합인가? 그래디언트
소실인가? 데이터 자체의 문제인가?), 결과를 남에게 설명하는 것까지 —
이 모든 과정을 스스로 겪어보는 것이 지난 10개 장의 개별 주제를 하나로
통합하는 가장 확실한 방법이다.

## 11.2 프로젝트 구조

- **코드**: 재현 가능해야 한다 — 다른 사람이 같은 코드를 실행하면
  (무작위성을 고정했을 때) 같은 결과가 나와야 한다. 데이터 전처리부터
  최종 평가까지 전체 파이프라인이 스크립트/노트북으로 정리돼 있어야
  한다.
- **리포트**: 문제 정의 → 방법론 → 실험 결과 → (필수) 수식적 정당화
  1개 이상 → 한계와 향후 개선 방향의 구조를 따른다.
- **포스터**: 발표(Chapter 12)에서 쓸 요약본 — 핵심 그림 1~2개(학습
  곡선, 결과 예시 등)와 가장 중요한 결론 3~4개로 압축한다.

## 11.3 프로젝트 주제 후보

자유 주제이지만, 다음과 같은 방향을 참고할 수 있다:

- **그래프 이상탐지**: 공개 합성 데이터를 이용해, 그래프신경망(GNN,
  이번 학기 범위 밖이지만 ML1 Chapter 10의 임베딩 개념과 이어진다)이나
  전통적 방법으로 비정상 노드/엣지를 탐지.
- **이미지 분류 응용**: ML1 Chapter 9(CNN)에서 배운 구조를 실제 이미지
  데이터셋에 적용, 전이학습(transfer learning) 시도.
- **간단한 챗봇/LLM 활용 프로젝트**: Chapter 2~4(LLM 파트)에서 배운
  프롬프팅 기법을 실제 과제(요약, 분류, 검색)에 응용.

**데이터 구하기**: 위 주제들에 쓸 데이터는 보통 다음 세 곳에서 구한다.

- **Kaggle**(kaggle.com/datasets): 정형데이터·이미지·텍스트를 가리지
  않는 가장 큰 데이터셋 저장소. 대회(Competition) 형태로 정리된
  데이터는 평가지표와 상위권 풀이까지 참고할 수 있어 특히 유용하다.
- **UCI Machine Learning Repository**(archive.ics.uci.edu): 고전적인
  정형 데이터셋 위주, 크기가 작아 빠른 실험과 손으로 구현한 모델을
  검증하는 데 적합하다.
- **Hugging Face Datasets**(huggingface.co/datasets): 텍스트·이미지
  데이터셋을 코드 몇 줄로 바로 불러올 수 있어, LLM/트랜스포머 관련
  프로젝트에 특히 편리하다.

## 11.4 팀 프로젝트에서 자주 마주치는 실전 문제들

이번 학기 배운 개념들이 실제 프로젝트에서 어떤 모습으로 나타나는지
미리 짚어본다:

- **데이터가 생각보다 지저분하다**: 결측값, 이상치, 클래스
  불균형(ML1 Chapter 3의 Precision/Recall이 왜 필요한지 다시 체감하게
  되는 지점) 등을 먼저 확인해야 한다.
- **학습이 안 될 때**: 손실이 줄지 않는다면 학습률(ML1 Chapter 2)이
  문제인지, 그래디언트 소실(ML1 Chapter 8)이 문제인지, 데이터 자체에
  신호가 없는지 순서대로 의심해봐야 한다.
- **검증 없이 모델을 고르지 않는다**: 학습 데이터에 대한 성능만 보고
  모델을 고르면 과적합된 모델을 최종안으로 선택하는 실수를 하기 쉽다 —
  반드시 별도의 검증/테스트 데이터로 최종 평가한다.

## 11.5 요구사항: 수식적 정당화 최소 1개

프로젝트 보고서에는 반드시 **수식적으로 정당화되는 선택 1개 이상**이
포함돼야 한다. 다음은 이 요구사항을 만족하는 예시들이다(프로젝트
주제에 맞게 변형):

1. 특정 손실함수를 골랐다면, 그 손실함수의 그래디언트가 왜 문제에
   적합한 형태를 갖는지 유도(ML1 Chapter 2, 3의 패턴 재사용).
2. 정규화 기법(dropout, 가중치 감쇠 등)을 썼다면, 그것이 과적합을
   어떻게 줄이는지 수식 또는 직관적 논증으로 설명(ML1 Chapter 8).
3. 모델 구조를 선택한 이유를, 파라미터 수/계산 복잡도 공식으로
   정량적으로 비교(ML1 Chapter 9의 CNN 파라미터 수 계산 패턴 재사용).
4. 강화학습/생성형 프로젝트라면, Chapter 5~10에서 배운 벨만방정식·
   ELBO·Nash 균형 같은 개념 중 하나를 실제 구현과 연결지어 설명.

이는 이번 학기 내내 강조된 "정확히 맞히는 코드"와 "왜 그렇게 작동하는지
아는 것"의 구분을, 프로젝트라는 더 큰 스케일에서도 유지하기 위함이다.

## 11.6 외부 제출 가능한 수준으로

이 프로젝트는 **코드 + 리포트 + 포스터** 3종 세트로 표준화해서
준비한다 — 나중에 외부 기관(대학 등)이 자료를 요청할 경우 즉시 제시할
수 있는 수준을 목표로 한다.

## 11.7 평가 기준

- 문제 정의의 명확성
- 방법론의 적절성(배운 개념을 올바르게 적용했는가)
- 수식적 정당화의 정확성과 깊이
- 결과의 정직한 보고(잘 안 된 부분을 숨기지 않고, 원인을 분석했는가)
- 코드의 재현 가능성
