### Dyna-Q 복습: 학습된 모델로 가상 경험 만들기

Chapter 7.3의 Dyna-Q는 세 가지를 동시에 했다: (1) 실제 환경과 상호작용해
경험을 쌓고, (2) 그 경험으로 간단한 모델 \\(\hat{P}(s'|s,a)\\),
\\(\hat{R}(s,a)\\)을 학습하고, (3) 그 모델로 **가상의 추가 경험**을
만들어 Q값을 더 많이 갱신했다. **모델기반 강화학습**(Model-Based RL)은
이 아이디어를 일반화한 이름이다 — 환경의 모델(전이확률과 보상함수, 또는
그 근사)을 학습하거나 이미 알고 있다면, 그 모델을 이용해 "실제로
행동해보지 않고도" 여러 수를 미리 시뮬레이션해볼 수 있다는 것이다.
Dyna-Q가 이 시뮬레이션을 **값 갱신**에 썼다면, 이번 장의 MCTS는 이걸
**지금 당장 어떤 행동을 할지 결정하는 데** 직접 쓴다는 점이 다르다.

### "모델을 안다"의 두 갈래와, 모델의 두 용도

Dyna-Q에는 한 가지 더 짚을 부분이 있다 — **모델이 откуда 왔는가**.
Chapter 7.3의 모델 \\(\hat{P}, \hat{R}\\)은 경험에서 쌓인 것이었다(각
\\((s,a)\\)에 대해 "마지막으로 관찰된 \\((r, s')\\)"을 기억하는 표).
이번 장의 바둑·체스에서 모델은 학습된 게 아니라 **규칙 자체**다 —
게임 규칙을 코드로 옮긴 것이지, 데이터로부터 추정한 근사가 아니다.
그래서 이 모델은 **오차가 전혀 없는 완벽한 모델**이다. 모델기반 RL에서는
이렇게 규칙으로 이미 정확히 주어진 모델을 **known model**(알려진
모델), Dyna-Q처럼 데이터로부터 학습한 모델을 **learned model**(학습된
모델)이라 구별한다.

모델이 어디에서 오든, 모델을 **무엇에 쓰느냐**도 두 갈래로 나뉜다 —
**학습**(값 개선)에 쓰는 경우와 **결정**(계획)에 쓰는 경우. Dyna-Q는
전자의 전형이다: 모델로 만든 가상 경험을 Q 갱신에 쓸 뿐, "지금 이
수에서 어떤 행동을 할지"를 직접 계산하지는 않는다. 15.2절의 MCTS는
후자의 전형이다: 모델을 (가상의) 행동 시나리오를 전개하는 데 써서
**지금 당장 둘 수**를 골라낸다. 이 두 축으로 정리하면:

| | **known model** (규칙이 주어짐) | **learned model** (데이터로 학습) |
|---|---|---|
| **값을 개선하는 데 쓰면(학습)** | 가치반복·정책반복 (Chapter 4) | Dyna-Q (Chapter 7.3) |
| **지금의 결정에 쓰면(계획)** | MCTS·AlphaZero (15.2절) | 로봇의 모델 예측 제어(MPC) 등 |

바둑 문제는 이 표의 **위쪽줄 오른쪽칸**에 앉는다 — 모델은 정확히
알지만 상태 공간이 너무 커서 "전체를 계산한다"(Chapter 4)가 불가능한
데서, "지금 필요한 것만 계산한다"(MCTS)로 방향을 튼 것이다. 로봇 같은
실제 환경은 보통 learned model쪽 — 모델을 데이터로부터 배워야 하거나
(물리 시뮬레이터로 만들거나) 아예 만들지 못한다. 아래줄 오른쪽칸
(학습된 모델로 계획)은 제어공학에서 오래된 **모델 예측
제어**(Model Predictive Control, MPC)에 해당한다 — 매 스텝마다
모델로 후보 행동 시퀀스를 미래로 시뮬레이션해 결과를 가장 좋게 하는
시퀀스의 첫 행동을 취하는 방식이다. MPC는 13~14장의 "모델 없이 배우는"
제어기 대신 **모델로 계획하는** 제어기로 산업용 로봇에 널리 쓰인다 —
**Dyna의 루프(모델 ↔ 계획으로 값/결정 개선)가 실 세계에서 어떻게
살아있는지**의 좋은 예시다.

**역사적 맥락**: MCTS의 계보는 학습 알고리즘 계보와 따로 자라왔다.
MCTS 알고리즘 자체는 2006년 Kocsis와 Szepesváry가 바둑 탐색에 제안한
것이 출발점이고, 그 선택 규칙(UCT)은 Chapter 2.2의 UCB 밴딧에서
직접 가져온 것이다 — 즉 "학습" 문헌의 도구를 "게임 AI"에 접목한
기술이었다. AlphaGo(2015)와 AlphaZero(2017)가 여기에 신경망을 엮어
바둑·체스·시구를 석권한 뒤, 이 일대가 ML 공통 언어로 "모델기반
RL"이라는 이름 아래 묶이기 시작했다. 그래서 "모델기반"은 고정된
'학파'가 아니라 **우산 용어**다 — "모델을 이용해 실제 환경과의
상호작용을 줄이는가"가 기준이고, 모델이 known/learned인지, 용도가
학습/계획인지는 그 안의 독립된 축이다.

### 모델이 "공짜"인 경우: 체스와 바둑

체스나 바둑 같은 게임에는 특별한 사정이 있다 — 규칙이 완벽하게
알려져 있다. "이 수를 두면 판이 정확히 이렇게 바뀐다"는 전이확률
\\(P(s'|s,a)\\)를 Dyna-Q처럼 데이터로부터 배울 필요가 전혀 없이, 이미
정확히 알고 있는 것이다(Chapter 4의 모델 기반 방법을 쓸 수 있는
이상적인 조건이다). 문제는 상태 수가 너무 많다는 것이다 — 바둑판의
가능한 국면 수는 약 \\(2 \times 10^{170}\\)으로 추정되는데, Chapter
4.3의 가치반복처럼 모든 상태를 한 번씩 순회하며 계산하는 방식은
근본적으로 불가능하다. 그래서 "지금 당장 놓인 상황 근처만" 깊이
파고드는 탐색이 필요해진다 — 이게 바로 15.2절 MCTS가 풀려는 문제다.

### 실습: 완전탐색이 가능한 경우와 불가능한 경우

"모델을 알고 있다"고 해서 항상 완전탐색(minimax)을 쓸 수 있는 건
아니다 — 상태 수가 관건이다. 틀만 같고 상태 수가 훨씬 작은
**틱택토**(3×3 빙고)에서 완전탐색이 실제로 가능한지 확인해보자:

```python
WIN_LINES = [(0,1,2),(3,4,5),(6,7,8),(0,3,6),(1,4,7),(2,5,8),(0,4,8),(2,4,6)]
nodes_visited = 0

def winner(board):
    for a, b, c in WIN_LINES:
        if board[a] != 0 and board[a] == board[b] == board[c]:
            return board[a]
    return 0

def minimax(board, player):
    global nodes_visited
    nodes_visited += 1
    w = winner(board)
    if w != 0:
        return w
    if all(x != 0 for x in board):
        return 0  # 무승부
    scores = []
    for i in range(9):
        if board[i] == 0:
            board[i] = player
            scores.append(minimax(board, -player))
            board[i] = 0
    return max(scores) if player == 1 else min(scores)

result = minimax([0]*9, player=1)
print("완전탐색 결과 (1=선공승, 0=무승부, -1=후공승):", result)
print("탐색한 전체 국면 수:", nodes_visited)
```

스크래치패드에서 실행 검증한 결과:

```
완전탐색 결과 (1=선공승, 0=무승부, -1=후공승): 0
탐색한 전체 국면 수: 549946
```

두 선수가 모두 최선을 다하면 틱택토는 항상 무승부로 끝난다 — 그리고
이 결론을 얻는 데 필요한 국면 수는 **549,946개**로, 평범한 노트북에서
1초도 안 걸려 전부 훑을 수 있다. 반면 바둑은 국면 수가 이보다
\\(10^{165}\\)배 이상 많다 — 완전탐색이라는 "정직한" 방법 자체가
아예 성립하지 않는 규모다. 이 격차가 바로 15.2절에서 다룰 MCTS가
필요한 이유다: 전체 트리를 다 보는 대신, 유망해 보이는 가지만
표본추출(sampling)로 골라서 깊이 파고든다.

### 손으로 계획 한 스텝: 알려진 모델에 가치반복을 적용

모델이 **완벽히 알려져** 있을 때 "계획"은 구체적으로 어떤 모습인가?
15.2절의 MCTS를 만나기 전에, 가장 단순한 형태인 **가치반복**(Chapter
4.3)을 먼저 손으로 한 번 들여다보자. 상태 \\(S\\)(출발), \\(X\\)(중간),
\\(T\\)(목표, 종료)의 3상태 예제를 만든다 — 각 상태에서 가능한 행동은
하나씩, 전이는 결정론적:

\\[S \xrightarrow{a} X \\;\\;(\text{보상 } 0), \qquad
X \xrightarrow{a} T \\;\\;(\text{보상 } +1), \qquad \gamma = 0.9\\]

참값은 거꾸로 대입(backward induction)으로 손에 바로 나온다 —
\\(Q(T)=0\\), \\(Q(X)=1+0.9\cdot 0=1\\),
\\(Q(S)=0+0.9\cdot 1=0.9\\). 그런데 이 값을 **모델만 갖고** 벨만방정식으로
계산해 보는 것이다. 가치반복의 한 반복(iteration)은 모든 \\((s,a)\\)에
대해 \\(Q(s,a) \leftarrow r + \gamma \max\_{a'} Q(s', a')\\)를 계산하는
것인데, 여기서 주의할 점은 **동기화(synchronous) 갱신**이라는 것이다 —
오른쪽의 모든 새 값을 *오래된* Q로 계산한 뒤, 한꺼번에 바꿔 넣는다
(Chapter 4.3과 같은 규칙).

- **반복 1** (초기 Q가 전부 0):
  \\(Q(X) \leftarrow 1 + 0.9 \cdot Q(T) = 1\\),
  \\(Q(S) \leftarrow 0 + 0.9 \cdot Q(X) = 0\\) — 아직 \\(Q(X)\\)가 0이므로.
- **반복 2**:
  \\(Q(S) \leftarrow 0 + 0.9 \cdot Q(X) = 0.9 \cdot 1 = 0.9\\).
  \\(Q(X)\\)는 변하지 않음.
- **반복 3**: 더 이상 아무 값도 변하지 않음 → **수렴**.

흥미로운 지점은 **\\(Q(S)\\)가 0에서 0.9로 도약하는 데 정확히 2번의
반복이 걸린** 것이다. 반복 1에서는 목표에서 링크 한 칸 떨어진 \\(X\\)만
"보상 +1이 2칸 뒤에 있다"는 사실을 알고 \\(Q(X)\\)가 1이 됐고,
2칸 떨어진 \\(Q(S)\\)는 아직 0이었다. 반복 2에서야 값이 모델의
엣지 \\(S \to X\\)를 타고 **한 칸 뒤로 퍼져** \\(S\\)까지 도착한
것이다. 즉 가치반복은 본질적으로 **한 반복당 값 정보가 모델 그래프를
따라 정확히 한 상태만큼 퍼져 나간다** — 목표에서 \\(d\\)칸 떨어진
상태의 \\(Q\\)값이 최종값에 도달하는 데 정확히 \\(d\\)번의 반복이
걸리고, \\(L\\)개 링크 체인의 전체 수렴(아무 값도 더 변하지 않는
시점)은 \\(L+1\\)번째 반복이다. 7.3절의 5×5 격자는 최단 경로 8스텝이라
9번 반복에 수렴한다 — 15.1 노트북에서 실제로 세어 확인한다.

이 "한 번에 한 칸"을 다른 관점에서 보자. 우리는 **모델을 안다** —
규칙을 안다 — 고므로, 체인을 **한 번에 전부 시뮬레이션**할 수 있다:
\\(S \xrightarrow{a} X \xrightarrow{a} T\\)를 두 스텝 시뮬레이션하면
보상 +1을 *바로* 본다. 가치반복이 2번의 반복에 걸쳐 발견한 것과
동일한 정보를, **깊이 있는 시뮬레이션 하나는 압축해 준다**. MCTS의
"시뮬레이션(끝까지 전개)+역전파(결과를 지나온 노드로 전달)"는
정확히 이 "깊이 시뮬레이션 + 결과 뒤로 전파"의 **표본추출 버전**이다
— 전체 체인이 아니라 "유망해 보이는" 체인을, 전체 상태를 대신
샘플링으로 골라 처리한다는 것만 다를 뿐. 15.2절에서 이 대응을
단계별로 다시 펼쳐 본다.

### "계획이 학습을 얼마나 빠르게 하는가"를 숫자로: Q-learning vs Dyna-Q

위 손계산은 모델이 **완벽히 알려진** 경우였다. 일반적인 경우는
모델을 **배워야 하는** 경우(Dyna-Q)다 — 학습된 모델로 계획하는 것이
학습을 실제로 얼마나 가속하는지, 7.3절의 5×5 격자 환경에서
숫자로 재보자. 환경은 7.3절과 똑같다: 출발 \\((4,0)\\), 목표
\\((0,4)\\), 4방향 이동, 이동마다 보상 \\(-1\\), 목표 도착 시 보상
\\(0\\)으로 에피소드 종료, \\(\gamma=1\\), \\(\alpha=0.1\\),
\\(\varepsilon=0.1\\). 참값은 손으로 나온다 — 최단 경로가 8스텝이므로
최적 리턴은 정확히 **\\(-7\\)**, 즉
\\(Q^{\*}(\text{출발}, \text{위}) = Q^{\*}(\text{출발}, \text{오른쪽})
= -7\\)이고 "아래/왼쪽"은 \\(-8\\)이다.

모델이 known이라면 가치반복이 9번 반복(= 계산 900회)으로 끝난다는
걸 방금 봤다 — 계획이 사실상 공짜인 경우다. 그런데 **learned model**
인 Dyna-Q에서는 얘기가 다르다: 실제 스텝 1회당 모델 엔트리가
1개만 늘어나므로, 모델 커버리지가 경험과 함께 서서히 자란다.
\\(planning\\_steps \in \\{0, 5, 10, 30\\}\\)을 400 에피소드로 비교
했다(시드 0, 시드 1~3도 유사한 범위 — [Colab
노트북](https://colab.research.google.com/github/SuminHan/book-ml/blob/main/notebooks/ml2/chapter15_1_model_based_dyna.ipynb)
에 완전한 코드가 있다):

| 설정 | "거의 최적"에 처음 진입 (25에피소드 평균 리턴 > −8) | 400에피소드 시 max Q(출발) |
|---|---|---|
| 가치반복 (known model) | 9번 반복 | 정확히 −7.00 |
| Q-learning (`planning_steps=0`) | 334 에피소드 | −6.61 |
| Dyna-Q (`planning_steps=5`) | 75 | −7.00 |
| Dyna-Q (`planning_steps=10`) | 52 | −7.00 |
| Dyna-Q (`planning_steps=30`) | 35 | −7.00 |

세 가지가 보인다. **(1) 가속은 극적** — 실제 상호작용 35회로,
계획 없이는 334회가 걸렸던 학습이 끝난다(약 **9.5배**). "실제
스텝 1회 = 로봇 이동 1초"인 환경이라면, 쓸 수 있는 수준(policy가
거의 최적)의 에이전트를 만드는 데 걸리는 벽시계가 같은 비율로
줄어드는 것이다. **(2) 한계 효과 감소** — 0→10으로 늘리면
334→52(약 6.4배)로 크게 빨라지지만, 10→30으로 더 늘려도 52→35
(약 1.5배)로만 줄어든다. 계획에 쓰는 계산량은 두 배로 늘어도
수렴 속도는 그 배수로 빨라지지 않는다 — `planning_steps`도
\\(\alpha\\), \\(\varepsilon\\)처럼 검증 성능으로 튜닝하는
하이퍼파라미터다(7.3절과 같은 결론). **(3) 목적지는 같다 —
다를 뿐인 것은 도로의 길이** — 순수 Q-learning도 400 에피소드
끝에 25개 모든 상태의 greedy 정책이 \\(Q^{\*}\\)와 일치하는 정책
(노트북에서 정책 불일치 0/25로 확인)에 도달한다. 계획이 바꾸는
것은 **도착하는 곳**이 아니라 **도달하는 데 드는 실제 상호작용
횟수**다. 결정론적 환경이라 학습된 모델 표는 결국 항상 정확
(경험한 (s,a)마다 예측이 항상 맞음)해지기 때문에, Dyna-Q는
결국 "공짜 모델"의 품질을 회복한다 — learned model이 known
model의 품질에 도달할 수 있는, 이 작은 환경에서는 가능한
경로다.

마지막 점이 이번 장의 줄거리를 잇는다: **Dyna-Q의 루프(learned
model ↔ 계획으로 값 개선)와 AlphaZero의 루프(신경망 ↔ MCTS
탐색)는 동일한 구조다** — "모델" 자리에 학습된 신경망, "Q
테이블" 자리에 가치 헤드, "계획 갱신" 자리에 MCTS 탐색이 앉을
뿐이다. 7.3절의 루프가 "모델로 Q를 개선하는 **학습**"이었다면,
15.2절의 MCTS는 "모델로 지금의 결정을 계산하는 **계획**" —
같은 두 요소 루프를 학습/계획이라는 두 축에서 다시 보는 셈이다.

### 자주 하는 실수: "모델이 있으니 학습이 필요 없다"는 착각

모델기반 RL을 처음 배울 때 흔한 오해가 있다 — "환경의 규칙을 완벽히
안다면, Chapter 4의 가치반복 같은 계획(planning) 알고리즘만으로
바로 최적 정책을 계산할 수 있으니 신경망 학습이 아예 필요 없다"는
생각이다. 위 실습에서 봤듯, 이건 상태 수가 작을 때만 맞는 말이다.
바둑처럼 상태 수가 천문학적인 문제에서는 "모델을 안다"는 것과
"그 모델로 최적 행동을 실제로 계산할 수 있다"는 것이 전혀 다른
얘기다 — 그래서 AlphaGo/AlphaZero(15.2절)는 여전히 신경망을
학습시킨다. 반대로 Dyna-Q(Chapter 7.3)처럼 모델이 데이터로부터
**학습된** 것일 때는, 그 모델 자체의 오차가 Q값에 누적되는 문제도
있다 — 초기에 몇 안 되는 경험으로 학습한 부정확한 모델을 가지고
가상 경험을 너무 많이 만들면, 그 부정확함이 그대로 Q값에 스며들어
오히려 학습을 방해할 수 있다. "모델기반"이라고 해서 공짜로 정확한
답을 주는 게 아니라, 모델의 정확도(또는 완전성)와 상태 공간의 크기
둘 다가 계획의 실현 가능성을 결정한다는 점을 기억해두자.

그리고 이 실수에는 **역방향** 버전도 있다 — "모델을 완벽히 안다면
(known model), 학습은 전혀 필요 없다"는 생각. 틱택토 실습은 이
주장이 상태 공간이 작을 때만 성립함을 보여줬고, 바둑의 상태 공간
은 너무 커서 완벽한 모델이 있어도 *전체 공간으로* 최적 행동을
계산할 수 없다. 그런데도 AlphaGo/AlphaZero가 규칙을 완전히
알면서도 **신경망을 학습**시킨 이유는 "모델을 배우기 위해서"가
아니라 **"탐색 공간을 압축하기 위해서"**다 — 모델(규칙)은 "이 수를
두면 판이 어떻게 변하는지"를, 즉 답이 **어디에 있는지**를 말해
준다. 신경망은 "어떤 갈림길부터 들여다볼 가치가 있는가"를, 즉
**어디를 볼지**를 말해 준다. MCTS는 신경망의 힌트를 따라 유망한
소수 가지만 골라 깊이 시뮬레이션하기 때문에, 제한된 시간(예: 한 수
당 2초) 안에 수백~수천 번의 시뮬레이션을 돌려 "모델이 아는 답"을
채굴할 수 있다. 모델을 몰랐다면 시뮬레이션 한 번도 못 돌렸을 텐데,
모델이 있어도 탐색 방향을 몰랐다면 시뮬레이션을 엉뚱한 가지만에
흘릴 뻔한 것이다. "모델을 안다"는 것이 계획의 **재료**를
준비해준다면, 학습은 계획의 **방향**을 준비해 준다 — 두 가지는
서로를 대체하지 않는다.

### 확인 문제

1. **체인 전파**: 3상태 손계산 예제의 체인을
   \\(S \to X\_1 \to \cdots \to X\_8 \to T\\)(10개 상태, 링크마다
   보상 0, 마지막 링크만 \\(+1\\), \\(\gamma=0.9\\))로 길게 늘리면,
   가치반복에서 \\(Q(S)\\)가 0이 아닌 값이 되려면 몇 번의 반복이
   필요한가? 같은 정보를 known model로 시뮬레이션만 하면 몇 스텝이면
   충분한가? 두 숫자를 답하고, 왜 이 두 숫자가 (거의) 같은
   "길이"인지 한 문장으로 설명하라. (힌트: "한 번에 한 칸"과
   "한 스텝에 한 칸".)

2. **틀린 모델**: 노트북의 `dyna_q_grid`에서 모델 갱신 줄
   `model[(s, a)] = (r, ns)`를
   `model[(s, a)] = (r, (4 - ns[0], 4 - ns[1]))`로 바꿔("다음 상태를
   실제 다음 상태의 판 대각 반대 자리라 예측하는" **틀린 모델**)
   `planning_steps=30`으로 400 에피소드 학습 후
   `max(Q[(START, a)] for a in range(4))`와 25에피소드 평균 리턴을
   보고 기록하라. 이 틀린 모델에서 출발점 \\((4,0)\\)의
   "아래"/"왼쪽" 모델 엔트리가 다음 상태를 **목표 \\((0,4)\\)**로
   예측함을 확인하고, 이 엔트리가 Q값과 greedy 정책을 어디로
   끌어당기는지 설명하라.

3. **도로 vs 목적지**: 5×5 격자 실험에서 `planning_steps=0`(순수
   Q-learning)도 400 에피소드 후 greedy 정책이 모든 25개 상태에서
   \\(Q^{\*}\\)와 일치했다(불일치 0/25). 그렇다면 계획(planning)이
   실제로 "가속"한 것은 무엇인가? 표의 "처음 진입" 열을 참고해
   한 문장으로 답하라.

4. **루프 대응**: Dyna-Q 루프의 세 요소(학습된 모델, Q 테이블,
   계획에 의한 가상 갱신)를 15.2절에서 소개한 AlphaZero의 구성
   요소(신경망의 정책/가치 헤드, MCTS)와 짝짓고, 각 대응을 한
   문장으로 설명하라.

### 자주 묻는 질문

**Q. Chapter 4의 가치반복도 "모델기반"인데, 왜 이 장에서 다시
"모델기반 RL"이라는 용어를 쓰나요?** 맞다, 가치반복도 모델기반이다.
차이는 스케일과 쓰임새다 — Chapter 4는 상태가 적은 문제에서 정책
전체를 미리 다 계산해 두는 데 썼다면, 이번 장(Dyna-Q, MCTS)은 상태가
너무 많아 정책 전체를 계산할 수 없을 때 "지금 이 상태에서 무엇을
할지"만 필요한 순간에 계산하는 데 초점을 맞춘다.

**Q. 그러면 모델기반 RL이 모델없는(model-free) RL(Chapter 5~11의
대부분)보다 항상 좋은가요?** 아니다. 모델기반 RL은 정확한 모델(또는
잘 학습된 모델)이 있을 때 데이터 효율이 훨씬 좋지만, 모델 자체를
학습하는 비용과 오차 누적 위험이 있다. 로봇 팔처럼 물리 법칙이
복잡한 환경에서는 정확한 모델을 만들기 어려워, Chapter 9~13처럼
모델 없이 직접 정책/가치를 배우는 쪽이 더 실용적인 경우가 많다.

**Q. Dyna-Q의 모델은 "학습된" 것이고, MCTS의 모델(규칙)은
"알려진" 것인데, 모델이 known이라면 왜 learned model(Dyna-Q) 얘기를
아예 안 해도 되나요?** 실제 환경의 대부분이 바둑처럼 규칙이
완전히 알려진 게임이 아니기 때문이다 — 로봇, 화학 공정, 교통,
인간-기계 상호작용에서는 모델이 데이터로부터 **배워**야 한다(또는
배우지 못한다). "공짜 모델"은 예외적인 특권이지 일반이지 않다 —
2010년대 이후의 모델기반 RL 연구(world model 계열 등)는 learned
model의 일반적 케이스를 다루는 것이 주된 목표다.

**Q. 이 절의 known model 경우와, Chapter 9 DQN의 경험
재사용(experience replay)은 관계가 있나요?** 둘 다 "손에 있는
정보를 더 많이 쓰자"는 기술이지만 재사용의 원천이 다르다. 경험
재생은 **실제** \\((s,a,r,s')\\) 튜플을 버퍼에서 다시 뽑아 쓰기
때문에 모델 오차가 없지만, 경험하지 않은 전이는 만들 수 없다.
모델 계획(Dyna)은 모델로 전이를 **생성**하기 때문에 경험이
커버하지 않은 상태까지 갈 수 있지만, 모델 오차를 짊어진다 —
"안전하지만 새것을 못 만든다"(재생) 대 "새것을 만들 수 있지만
오차가 동반된다"(계획). 9장 이후의 모델기반 DQN 변형들은 학습된
신경망 모델을 얹어 이 둘을 결합하는 방향으로 나아간다.

> **핵심 정리**: 모델기반 RL = **모델을 이용해 실제 환경과의
> 상호작용을 줄이는 방법들의 묶음**. 모델의 출처(known / learned)와
> 용도(값 개선 = 학습 / 지금의 결정 = 계획)라는 두 축이 독립적이다:
> 가치반복은 "known + 학습", Dyna-Q는 "learned + 학습", MCTS는
> "known + 계획", 그리고 AlphaZero는 신경망이 모델의 역할을 맡은
> 확대판 Dyna 루프다. "모델을 안다"는 것이 계획의 재료를,
> "학습"은 계획의 방향을 준비한다 — 둘은 서로를 대체하지 않는다.

**모델기반 RL은 하나의 알고리즘이 아니라 "모델이 실제 상호작용의
일부를 대신할 수 있다"는 한 가지 아이디어로 묶인 방법들의
가족이다 — 그리고 모델이 known인지 learned인지, 학습에 쓰는지
지금의 결정에 쓰는지,는 두 개의 독립된 축으로 나눠지는
배경이 이번 절의 전체 그림이다. 다음 15.2절에서는 이 축들의
가장 날카로운 교차점 — known model로 "지금의 결정"을 계산하는
MCTS — 을 이론과 실습으로 직접 다룬다.**
