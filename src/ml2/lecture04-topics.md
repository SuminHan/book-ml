## 언어모델링: 다음 토큰 예측

LLM은 텍스트를 **토큰**(token)(단어 전체이거나, 더 흔하게는 단어의 일부 조각)의
시퀀스로 다룬다. 사전학습의 목표는 지금까지의 토큰들이 주어졌을 때, 다음 토큰의
확률분포를 예측하는 것이다:

\\[P(x_t \mid x_1, x_2, \ldots, x_{t-1})\\]

이 확률은 W03에서 배운 Transformer(정확히는 미래 토큰을 보지 못하게 마스킹한
decoder-only Transformer)로 계산된다. 학습은 실제 다음 토큰과 예측 확률분포 사이의
교차 엔트로피 손실(W03 이전, W03에서 다룬 분류 손실과 같은 형태)을 최소화하는
방향으로 진행된다.

```python
def next_token_probs(logits):
    # logits: 어휘 사전의 각 토큰에 대한 원점수(raw score)
    # softmax를 적용하면 "다음 토큰이 각각일 확률"이 된다
    return softmax(logits)
```

## 사전학습 vs 파인튜닝

| | 사전학습(Pretraining) | 파인튜닝(Fine-tuning) |
|---|---|---|
| 데이터 | 인터넷 규모의 방대한 텍스트 | 특정 목적에 맞는 비교적 적은 데이터 |
| 목표 | 다음 토큰 예측(비지도) | 특정 작업(대화, 지시 따르기 등)에 맞춘 지도학습 |
| 결과 | 폭넓지만 다듬어지지 않은 능력 | 목적에 맞게 다듬어진 행동 |

사전학습은 계산 비용이 막대하지만(수천 개의 GPU로 몇 주~몇 달), 파인튜닝은 상대적으로
적은 자원으로 가능하다 — "기초를 다시 배우지 않고, 이미 아는 것을 특정 방향으로
다듬는다"는 것이 파인튜닝의 효율성의 핵심이다.

## 프롬프팅 기법

- **Zero-shot**: 예시 없이 지시문만 주고 바로 요청 ("이 문장을 한국어로 번역해줘:
  ...").
- **Few-shot**: 몇 개의 입출력 예시를 프롬프트에 포함시켜, 모델이 패턴을 파악하고
  따라하게 유도.
- **Chain-of-Thought**: "단계별로 생각해봐"처럼, 최종 답 전에 중간 추론 과정을
  출력하도록 유도 — 복잡한 추론 문제에서 정답률을 크게 높이는 경우가 많다.

## 왜 프롬프팅이 통하는가

사전학습 데이터에는 "질문-답변", "예시-패턴" 형태의 텍스트가 이미 무수히 포함돼
있다. 모델은 "다음 토큰 예측"을 통해 이런 패턴 자체를 이미 학습해뒀으므로, 프롬프트
안에 비슷한 패턴을 보여주면 그 패턴을 이어가는 방향으로 다음 토큰을 예측한다 — 새로운
지식을 학습하는 게 아니라, **이미 갖고 있는 능력 중 어떤 것을 꺼내 쓸지를 프롬프트가
가리키는 것**에 가깝다.

## 한계

LLM은 사실이 아닌 그럴듯한 문장을 자신 있게 만들어내기도 한다(**환각,
hallucination**) — "다음 토큰으로 그럴듯한 것"을 예측하도록 학습됐을 뿐, 사실
여부를 검증하는 과정이 내장돼 있지 않기 때문이다. 이 한계는 지금도 활발히 연구되는
문제이며, 이 학기의 범위를 넘어선다 — 다만 "왜 이런 한계가 생기는가"를 사전학습
목표(다음 토큰 예측) 자체에서 짚어낼 수 있다는 점은 기억해둘 만하다.
