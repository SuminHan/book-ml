# Topics Covered

## 강화학습의 구성 요소

- **상태(State) \\(s\\)**: 에이전트가 처한 상황을 나타내는 정보 (예: 바둑판의 현재
  배치, 게임 캐릭터의 위치).
- **행동(Action) \\(a\\)**: 그 상태에서 에이전트가 선택할 수 있는 것 (예: 바둑돌을
  놓을 위치).
- **보상(Reward) \\(r\\)**: 행동의 결과로 즉시 받는 숫자 신호 (예: 게임에서 이기면
  +1, 지면 -1).
- **정책(Policy) \\(\pi\\)**: 상태를 행동으로 매핑하는 전략 — \\(\pi(s) = a\\)(결정론적)
  또는 \\(\pi(a|s)\\)(확률적, 상태 \\(s\\)에서 행동 \\(a\\)를 선택할 확률).

에이전트는 환경과 계속 상호작용한다: 상태 \\(s_0\\)에서 행동 \\(a_0\\)를 하면 보상
\\(r_0\\)를 받고 새 상태 \\(s_1\\)이 되며, 이 과정이 반복된다. 이 상태-행동-보상의
연속을 **에피소드**(episode) 또는 **궤적**(trajectory)이라 부른다.

## 지도학습과의 결정적 차이

| | 지도학습 | 강화학습 |
|---|---|---|
| 무엇이 주어지는가 | (입력, 정답) 쌍 | (상태, 행동, 보상)의 연속 |
| "정답"이 있는가 | 있음 | 없음 — 보상만 있음 |
| 데이터의 출처 | 미리 고정된 데이터셋 | 에이전트 스스로의 행동으로 생성 |
| 시간의 역할 | 각 샘플이 독립적 | 지금의 행동이 미래 상태에 영향을 줌 |

가장 중요한 차이는 **지연된 보상**(delayed reward)이다: 체스에서 17번째 수가 좋았는지는
그 수를 둔 직후가 아니라, 게임이 끝나야(또는 한참 지나야) 알 수 있다. "지금 이
행동이 최종 결과에 얼마나 기여했는가"를 알아내는 문제(신용 할당 문제, credit
assignment problem)가 RL을 어렵게 만드는 핵심 이유다.

## 왜 "누적" 보상인가

당장의 보상만 최대화하면 근시안적인 전략이 나온다 — 체스에서 당장 말 하나를 따먹는
수가, 몇 수 뒤에 체크메이트를 당하는 함정일 수 있다. 그래서 RL은 **지금부터 끝까지
받을 보상의 총합**(누적 보상, return)을 최대화하도록 설계된다. 보통 먼 미래의 보상은
할인율(discount factor) \\(\gamma\\)(0~1 사이)로 조금씩 깎아서 더한다 — "당장의 이득이
먼 미래의 같은 이득보다 조금 더 가치있다"는 상식을 반영한 것이다. 이 개념(할인된 누적
보상)은 ML2 W05에서 벨만방정식으로 정식화된다.

## 이번 주 손유도 과제 예고

작은 3-state MDP(마르코프 결정 과정, Markov Decision Process — 상태·행동·보상·전이를
정식화한 수학적 틀)를 놓고, "각 상태의 가치(그 상태에서 시작했을 때 기대할 수 있는
누적 보상)"를 손으로 직접 계산해본다. 이 계산의 정식 명칭이 **벨만방정식**(Bellman
equation)이며, ML2 W05에서 훨씬 일반적인 형태로 다시 만난다.
